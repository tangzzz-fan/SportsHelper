# 01: 校对页留痕——把用户改过的数字接住，并在下一次用它

**What to build:** 用户在「校对」页把 `深蹲 3 组` 改成 `2 组`，这个改动现在**存完就消失了**。把它按「动作 + 字段 → 改成什么」记下来，连着两次改成同一个值，下次导入直接用你的值，并在「我替你判断了这些，请核对」里写清这是第几次。

**Blocked by:** None

## 为什么先做这一件

`PlanReviewView.onApply` 里，`row.sets` 与 `result.sets` 是原值与新值的唯一一次同框。`PlanEditing.updateItem` 执行完，原值就被覆盖，**从此不可恢复**。

其余两个候选（变更史、偏好线）都可以晚做——它们要的数据将来会有。这一件不行：每一个没被记下的导入，都是一次永久丢失。**只有「信号正在消失」够格插队。**

## 记什么、不记什么

| 记 | 不记 | 为什么 |
|---|---|---|
| 组数、每组量（次数 / 秒 / 米） | 休息时间 | 休息是噪声，同一动作在不同计划里本来就该不同 |
| `catalogId` 能对上库的动作 | 「保留原名」的行 | 记住一个假 id 会污染所有同名行 |
| 改成什么（`to`）+ 连着几次 | 从什么改成什么 | `from` 每次都不同，进 key 就永远凑不够两次 |

**计数口径是「连续一致」，不是「累计一致」**：第二次改成别的值，计数清零重来。累计会把三周前的旧想法一直套在今天。

## 怎么用

- 阈值 2。第一次改只记下，什么都不做。
- 生效时改的是**解析结果**，不是已存的计划——所以它发生在 `parse()`，早于用户看到校对页。
- 每一处改动都写进 `draft.assumptions`，卡片会显示「深蹲 组数 3 → 2 组（你连着 2 次这么改）」。同一动作排了三天只出现一次；超过 4 处折成「还有 N 处按你上次的改法处理了」。
- 解析结果本来就等于记忆值时**不写说明**——没改动就没有可披露的东西。

## 验收

- [x] `CorrectionMemory`（Core，纯值类型、`Codable`）——`record` / `settled` / `applying(to plan:)` / `applying(to draft:)`
- [x] 10 条测试：一次不生效、两次生效、改主意清零、只动目标字段、秒数动作的文案、已相等时沉默、说明进卡片、假 id 不收、字段互不干扰、编解码往返、同动作多天去重、说明上限
- [x] `CorrectionStore`（UserDefaults，键 `dk.correction.memory`）
- [x] `ImportView.parse()` 应用；`PlanReviewView.onApply` 记录
- [x] 词表新增「纠错 / 演进 / 改法记忆」三条

## 不做什么

- **不发明「学习用户偏好」**。这是纠错，不是个体化：它有客观答案（用户说要 2 组，就是要 2 组），不涉及剂量判断，也不进 `DoseAdjustment`。
- **不改 `AliasMemory` 的「最后一条覆盖」**。它该改成计数制，但那是另一张票：存储格式要迁移，且它已经能工作，混进来会让本票的 diff 说不清哪一处是为什么。
- **不记删除**。校对页现在没有删除动作；要记它得先有那个交互。

## 已知缺口

用户自定义动作（`UserExercise`，不在 `ExerciseLibrary` 里）不参与改法记忆。要不要放开取决于「自定义动作会不会在不同计划里重复出现」，现在没有数据。
