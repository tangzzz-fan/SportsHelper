# 03: 一次能看见、能采纳的加量提案

**What to build:** 从记录到新计划的完整一条路。只实现「加次数」一条规则，但每一层都通——这是 tracer bullet。

**Blocked by:** 01, 02

- [ ] `DoseAdjustment.propose(plan:logs:sessions:now:) -> PlanProposal?`，本期只实现「目标次数未到该动作上限 → +2」
- [ ] `PlanProposal` / `Change` 模型；`reason` 必须引用具体记录（「上周三组都多做 2 个」），不允许「根据你的表现」
- [ ] 计划页顶部一张提案卡：改了什么、为什么、两个按钮（`就这样` / `不用`）
- [ ] 采纳后：计划立即替换，`revision` +1，**本次训练就用新数字**
- [ ] 拒绝后：计划不动，且记下这次拒绝（07 会用它）
- [ ] 测试：连续 2 次全组多做 → 有提案；只 1 次 → nil
- [ ] 测试：`rpe ≤ 3` 的组不计入「多做」——那组还有余力，说明目标设低了但身体没被推到
- [ ] 测试：`revision` 只在采纳时递增；拒绝、`nil`、外来计划静默都不递增

**边界**：规则故意只有一条。04 之后只往里加规则，不改这层结构。如果加规则要改 `propose` 的签名或返回类型，说明这一票切错了。

**判据**：这一票做完，能在模拟器上完整演示一次「练两组 → 下周看到提案 → 点就这样 → 数字变了 → 立刻按新数字练」。
