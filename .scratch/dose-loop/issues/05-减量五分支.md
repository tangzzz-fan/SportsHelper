# 05: 减量的五个分支

**What to build:** 用户选的跳过原因不再是统计，而是处方的输入。五个原因走五条不同的路。

**Blocked by:** 03

- [ ] `noTime` → 砍末位辅助动作（仅在当天动作数 > 5 时），组数不动
- [ ] `tooHard` → 降负荷 5–10%，组数不动
- [ ] `pain` → 该动作降 20%（`safety` 的优先级见 06）
- [ ] `noEquipment` → 换动作（`alternativeId`），不降量
- [ ] `other` → 不动，返回 nil
- [ ] 换动作后新动作从该动作的下限重新开始，不迁历史剂量
- [ ] 测试：五个分支各一条；`noTime` 在动作数 ≤5 时不砍
- [ ] 测试：`alternativeId` 为空的动作，`noEquipment` 降级为 `other`

**这一票的实质**：`SkipReason` 五个值从 2026-10-22 就存在，写进了库，从来没有被读过。这一票是让它第一次成为决策输入。一个只用来统计的「原因」是问卷；用来改处方的才是判断。

**边界**：不给用户看「因为你选了没时间，所以砍掉了登山跑」这样的因果解释链——一句话说不清，说清了像辩解。只在提案卡上写结果和一句理由。
