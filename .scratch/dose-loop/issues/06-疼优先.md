# 06: 疼优先于一切

**What to build:** 上周有动作做到疼时，这一周的提案先处理疼，加量往后排。

**Blocked by:** 05

- [ ] `kind` 冲突时 `safety > rebuild > swap > dose`
- [ ] `pain` 一次即触发，不需要连续两次（累要两次，疼不要）
- [ ] 同一提案里 `safety` 的 change 排在最前，且用不同的视觉层级
- [ ] `safety` 文案不写「建议」，写「这周先这样」——它不是征求意见，是保护
- [ ] 测试：上周既有「疼」又有「该加量」→ 出 safety，且提案里不出现任何加量项
- [ ] 测试：`pain` 与 `other` 同时出现时仍触发

**取舍**：安全也走提案，不走自动生效。ADR-0004 没有例外——用户仍要自己点。但文案与排序要让他在一眼之内看出「这是保护，不是优化」，否则「计划变了」会被读成「App 又改我东西」。

**不做**：不做「疼痛评分」「疼在哪里」的追问。追问会把训练页变成问诊，而这一票要解决的是「别装作没看见」，不是「诊断」。

## 落地（2026-10-25）

`safety` 在 `propose` 里排第一，且**不看拒绝记录**（保护不需要许可，但仍要用户点）。文案是「上周 X 做到疼。这周先轻一点，不加量。」——不是「建议」，也不是「根据你的表现」。

降幅：有重量 80%，没重量次数 80%（不低于 5），时间型动作减一组。有测试锁住「疼和该加量同时出现时，提案里没有任何加量项」。
