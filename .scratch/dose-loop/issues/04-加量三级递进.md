# 04: 加量的三级递进

**What to build:** 次数、负荷、组数三条杠杆，按固定顺序一次只动一条。

**Blocked by:** 03

- [ ] 次数未到该动作上限 → 加次数 +2
- [ ] 次数到顶且连续 2 次全组多做 ≥1 次 → 加负荷 2.5%，次数回落到下限
- [ ] 负荷到顶（自重，或已用最大档）→ 加组数 +1，上限 +2
- [ ] 同一提案里不允许出现两种 `field`
- [ ] 三套 `reason` 各自说清「为什么是这一档，不是下一档」——用户要能看出还有下一阶
- [ ] 测试：三级各自触发与不触发；同时满足两条时只取前一级
- [ ] 测试：自重动作跳过加负荷，直接进加组数
- [ ] 测试：`load` 为 0（未指定重量）的动作，不产出 `load` 的 change

**为什么是这个顺序**：加次数先耗尽当前重量的余量，再加重，是唯一能在「只有一对哑铃」的约束下走通的路。反过来先加重，次数会掉到下限以下，动作变形，学不会。

**一个必须承认的限制**：`load` 现在大多是 0（AI 生成的计划不指定重量）。这一票不解决「该拿多重」，只解决「已知重量时怎么加」。起始重量属于另一个问题。

## 落地（2026-10-25）

三级都通：`lever(for:)` 判「这一档还能不能动」，`doseProposal` 取所有候选里**最低**的一档，只收这一档的动作——所以同一提案永远只有一种 `field`（`oneLeverPerProposal` 锁住）。

三套理由各说各的下一阶：加次数时只说「每组都多做了」；加负荷时说「次数到顶（N 次）+ 加重一档」；加组数时说「次数到顶，也没有可加的重量」。

**两处临时口径**：组数上限用绝对值 5（原计划没有基线可参照「原 +2」）；次数上限 15（超过就不是力量刺激）。两者都在 `DoseAdjustment` 的常量里，改一处即可。
