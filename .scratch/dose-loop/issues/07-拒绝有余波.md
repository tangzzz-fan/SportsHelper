# 07: 拒绝要有余波

**What to build:** 用户说不，就得算数。不再提同一条，连拒三次就整体安静一段时间。

**Blocked by:** 03

- [ ] 记下被拒绝的提案指纹：`kind` + `catalogId` + `field`
- [ ] 同指纹不再提
- [ ] 连续三次拒绝 → 静默一个周期
- [ ] 静默期内用户主动看提案（进入调整入口）不清零计数；只有**采纳**才清零
- [ ] 测试：拒绝一次后同一条不提；换一个动作仍可提
- [ ] 测试：三次后整体静默；静默期内 `propose` 返回 nil
- [ ] 测试：静默期内计划页**不显示**「已暂停建议」之类的话术

**为什么静默期不显示提示**：告诉用户「你拒绝太多了所以我不提了」，等于让他为自己的选择解释。他不采纳就是不想，不是要谈判。

**边界**：不做「为什么不采纳」的追问，也不做「换一个方案试试吗」。追问把拒绝变成了议价。

## 落地（2026-10-25）

`ProposalMemory` 记三样：被拒指纹、连续拒绝次数、采纳史。`propose` 里 `.dose` 与 `.swap` 会跳过被拒过的同一指纹；`safety`、`rebuild`、降量（`isDeload`）不受此限——保护与缓一缓不能因为被拒就闭嘴。

连拒三次 → `isSilenced`，任何提案都不再产出，且**界面不显示任何「已暂停建议」的文案**。只有采纳才清零。

`prefer` 边界：不做「为什么不采纳」，不做「换一个试试」。
