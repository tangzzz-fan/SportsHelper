# 教练音色复原 · coach-voice

起因（2026-10-25）：把 Apple Workout Buddy 的技术方案拆开，看能不能自己复原一条「教练音色」的线。

## 1. Apple 到底做了什么

### 已知事实

| 事实 | 出处 |
|---|---|
| watchOS 26 的 Workout 里，Workout Buddy 在训练中实时说话 | 官方发布 + 多家实测 |
| **不是录音，没有脚本**，每次生成都不一样 | CNET 采访 Apple 的 Caldbeck：「This is not a recording. There was no script.」 |
| 语音模型**用 28 位 Fitness+ 教练的声音训练**，用户从 3 个声音里选 | CNET / mac-os.org 上手 |
| 输入是实时数据：配速、心率、活动圆环、训练负荷、历史 | 同上 |
| 端侧 + 私有云（Apple Intelligence / PCC） | 同上 |
| 首发只有英语，先覆盖跑步、步行、骑行、力量 | 同上 |

### 结构拆解（四层）

| 层 | Apple | 我们 | 差距 |
|---|---|---|---|
| 事件源 | 心率 / 配速 / 里程碑（连续信号，噪声大） | 组 / 休息 / 动作（离散、结构化） | **我们更简单** |
| 话术决策 | 未公开 | `WorkoutAnnouncement` + 预算 + 优先级 | 已有，且可测 |
| 音色 | 28 位教练训练出的模型 | 系统 TTS 最高档 | **缺口就在这** |
| 合成 | 端侧 + PCC | `AVSpeechSynthesizer` | 同上是缺口 |

**关键判断：他们真正难的是第一层和第三层。** 第一层（从心率噪声里判断"该说话了"）我们没有——我们的触发点是确定的。第三层（音色）我们没有，但他们花了十年。

### 他们踩的坑（不用自己再踩一遍）

1. **话痨**：心率在目标线上下抖时「每隔几秒」提醒一次，官方必须给逐项开关。→ 我们一组最多 3 条的上限方向是对的。
2. **语气与内容失配**：念完「爬升 230 英尺」接一句「这很温和！」，用力过猛听起来像讽刺。→ **语气是文案给的，不是音色给的**。
3. **只有英语**：说明话术要按语言重写，这条路的成本在内容不在模型。

## 2. 为什么我们可以离线解决

Apple 必须实时生成，因为它的句子是无限组合（配速、心率、里程碑任意拼接）。**我们的句子集合是封闭的**：

- 43 个动作名
- 数字 0–60
- 单位：次 / 秒 / 分 / 组 / 每侧
- 连接词：第、共、休息、接下来、完成、另有

按 `WorkoutAnnouncement` 的六种句式展开，**实测 316 条片段**（`VoiceClipBank.inventory`，含动作名 43、组数 1–20、共 N 组 1–30、次数 1–30、每侧 1–20、秒 5–120 步长 5、百分比 0–100 步长 5 等）。22.05kHz 单声道 16 位，约 6MB。

也就是说：**「教练音色」对我们不是一个实时合成问题，而是一个离线渲染 + 运行时拼接问题。**

## 3. 复原路线

### 阶段 0：验证架构，不验证音色（已落）

- `DongKeCore/Workout/VoiceClipBank.swift`：把整句切成短语（最长匹配），切不出来返回 `.fallback`
- `scripts/render-voice-clips.sh`：`say` 渲染 **496 条** WAV 到 `VoiceClips/`（不进 git，见该目录 README）
- `DongKe/Services/ClipSpeechRenderer.swift`：`AVAudioEngine` 拼接播放，段间 70ms 静音，缺失片段整句回落系统 TTS
- 开关：`DK_VOICE_CLIPS=0` 强制走系统 TTS，用来 A/B

**零回落（2026-10-25 补齐）：** 一节课里不允许出现两种音色，否则判据不成立——听到的不是"拼接好不好"，而是"拼接 + TTS 混着"。为此：

- 开场句去掉当天主题名（AI 生成的自由文本，录不了），改成「开始训练，共 9 组，3 个动作」
- 动作库的 **150 条要点**全部入词表（有界：50 个动作 × 2–3 句）
- 守卫测试 `fullSessionIsFullyCovered`：走一遍循环 + 多区块计划的所有播报，断言全部能切分。**写完当场抓到两个漏录**——「N 分钟」（默认 60 秒休息就命中）与「N 个动作」

**判据：拼接后能不能听懂、有没有"机器人在念单词"的感觉。** 这一步就能证伪最大的风险。

### 阶段 1：换生成器（1–2 天）

用 **CosyVoice2-0.5B**（Apache-2.0，零样本克隆，3 秒参考音）重渲染同一批 **496 条**。

- 参考音自己录 8–12 秒（避免任何授权问题）
- 在 Mac 上离线跑，只需一次，不进 App
- 判据：数字自然、句尾不飘、与参考音像同一个人

### 阶段 2：盲听 A/B

同一节课、同一台设备，系统 TTS vs 音条，3 个人盲听选。**用户是唯一裁判**。

### 阶段 3：切换默认 + 兜底

音条命中 → 播音频；未命中（新动作 / 新单位 / 新语言）→ 回落到系统 TTS。这正是 ADR-0007「一套语义两个引擎」的第三档，端口已经支持。

**但设计目标是零回落**：兜底是安全网，不是常态。一节课里只要有一句回落，听到的就是两种音色。加新动作时重跑 `scripts/render-voice-clips.sh`，守卫测试保证不会漏。

## 4. 判据（写死，与 ADR-0007 的三条门槛对齐）

| 项 | 门槛 |
|---|---|
| 首音 | < 80ms（`AVAudioPlayer` 实测） |
| 单句时长偏差 | < 15%（相对系统 TTS 基线） |
| 体积 | < 4MB |
| 许可 | 模型 Apache-2.0（CosyVoice2 / IndexTTS2），参考音自录 |
| 兜底 | 音条缺失必须回落系统 TTS，不能静默 |

> 排除项：**macOS `say` 生成的音频不能上架**（Apple 语音只授权个人使用）。它只用于阶段 0 的内部原型。

## 6. 风险

| 风险 | 处置 |
|---|---|
| **拼接感**（coarticulation，词与词之间不连贯） | 阶段 0 就能证伪；过不了一切停止 |
| 音条与文案漂移（改了文案忘了重渲染） | 音条清单必须是**生成**的，不是手写的；改文案时单测会红 |
| 117 条覆盖不全 | 兜底回落系统 TTS，不追求 100% 覆盖 |
| CosyVoice2 中文质量 | 阶段 1 的判据就是它；不行换 IndexTTS2（Apache-2.0） |
| 模型体积 | 不随包，只随音频（2MB） |

## 7. 与既有决策的关系

ADR-0007 说「换引擎要三条同时成立：许可干净、RTF < 0.5、体积可接受」。**这条线绕开了 RTF 和体积**——因为运行时不跑模型。它只保留许可一条，并新增一条「拼接不违和」。

这不是推翻 ADR-0007，是补上它没考虑到的第四条路：**把合成搬到构建期**。
