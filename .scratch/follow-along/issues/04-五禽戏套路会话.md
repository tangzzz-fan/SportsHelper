# 04: 五禽戏套路会话

**What to build:** 用户选「五禽戏」后进入一段连续跟练：12 段（起势 + 10 式 + 收势），每段有时长与口令，语音播报报下一式，不给「组」。练完记一条「练了 14 分钟」。

**Blocked by:** 03（要有「直接开始」这个入口才走得到）

**Status:** 待开工（2026-10-25 定案，见 ADR 0001 / 0002）

## 条目

- [ ] 新增 `Routine`：段序列，`RoutineSegment { id, title, seconds, cue, steps, figureId }`
- [ ] 新增 `RoutineCatalog.all`：入口与播放页只读这张表，不硬编码「五禽戏」
- [ ] 五禽戏 12 段（起势 + 10 式 + 收势）、八段锦 9 段（预备 + 8 式）
- [ ] 播放页：连续计时，复用 `endAt` 绝对时间回前台重算，不接 `WorkoutFlowModel`
- [ ] 语音播报复用现有的关键节点播报，文案里不出现「组」
- [ ] 段内提示按 ticket 05 的三种类型走（focus / remaining / encourage），每段最多 1 条中段提示
- [ ] 记录只写时长与完成与否，**不进完成率 / 降阶率分母**
- [ ] 每段图示按 `figureId` 取，先用现有绘制脚本出简版

## 加一套传统内容要动什么（适配器的验收口径）

判据只有一条：**加「站桩」这类新内容，要不要改代码。**

| 层 | 缝 | 加一套要动 |
|---|---|---|
| 内容 | `RoutineCatalog.all` | 加一个 `Routine` 字面量 |
| 图示 | `FigureSource`（已在 `ExerciseFigure.swift:134`） | 加图数据，播放页不动 |
| 入口 | 「直接开始」遍历 `RoutineCatalog.all` | 不动 |

**站桩是模型的自检用例**：它不是动作序列，是单段长保持（10–20 分钟）。`Routine` 若能把它表达成「1 段 × 900 秒」而不需要任何特例，模型就是对的；若需要新字段或分支，说明模型选错了。

## 不做

- **不给每式建 `ExerciseEntry`**：那会让「虎举」出现在动作库里，用户能在力量计划里排出「虎举 3 组 12 次」。套路段与动作是两个内容域，只在图示上共用一条缝。
- **不做插件协议 / 远程内容包**：现在只有两套内容，预留外部来源是推测性抽象。真接远端内容时，照 `FigureSource` 的样子加一层即可。

## 边界

不做：视频、自定义套路、套路排进周计划、配乐。

## 防腐层

图示必须经 `FigureSource` 取，播放页不得直接读 `GeneratedFigureData`。后面统一整体风格时只换这个实现，播放页与数据不动。

## 验收

- 连续跟完 12 段；中途退到后台再回来，剩余时间正确
- 播报文案里不出现「第 N 组」「共 M 组」
- 练完在历史里显示一条时长记录，且总结页的完成率统计不受影响
- 换掉 `FigureSource` 的实现，播放页无需改动

## 边界

不做：视频、自定义套路、套路排进周计划、配乐。
