# 08: 器械档位与剂量读实际重量

**What to build:** 第一次练负重动作时，App 问一次器械是可调还是固定档；之后加量提案给出买得到的重量；用户自己加重导致的次数下降，不会被记成退步或「太累」。

**Blocked by:** 02, 03

**状态：** 已落地（2026-11-18）。896 条单测全绿（新增 18 条）；模拟器截图确认首次进训练页自动弹「重量档位」；UI 用例带着 `-dk.load.rackAsked YES` 跑过，面板不挡路。

- [x] `LoadRack`（Core 值类型）：`adjustable(step 2.5 / 5)` 或 `fixed(plates)`；`next(after:)` 给下一个买得到的重量，`snapped(_:)` 把买不到的数字拉回最近档位
- [x] `LoadRackStore`：`UserDefaults` 存 JSON + `hasAnswered`，默认 2.5kg 步进；设置页「重量档位」一行可改
- [x] 首次进训练页且当前动作有负重时自动问一次；取消也算问过，之后不再自动弹
- [x] 加量提案走档位：`lever(for:rack:)` 在没有更重档位时改判加组；`nextLoad(after:rack:steps:)` 落在真实档位上
- [x] 耐受记忆仍然有用：撑得住的人一次跳两档（20 → 25），其余一档（20 → 22.5）——不再出现 20.3kg 这种买不到的数
- [x] `selfLoadedProposal`：连续两次、每组都用同一个更重的实际重量且都完成 → 把处方改成那个重量，次数不动，理由不提「太累」
- [x] **改了三处旧测试的期望值**（`DoseRulesTests` 的 20.3 / 20.5 / 21 与 `loadComesSecond` 的 20.5）。它们编码的正是 1118 指出的问题——按百分比加重会产出买不到的重量，现在换成档位
- [x] 单测：档位进退位与取整、无更重档位转加组、两档跳、两次自己加重出纠偏、单次不触发、次数下降不判成失败
- [x] 变异验证一次（把跳档循环固定成 1 档后「一次跳两档」红）
