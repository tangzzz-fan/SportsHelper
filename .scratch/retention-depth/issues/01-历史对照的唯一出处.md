# 01: 历史对照的唯一出处

**What to build:** 一个纯函数，从 `[SetLog]` 算出「这个动作上次做到哪、历史最高是多少、一共练过几节」。训练页、破纪录判定、周报三处都只读它的结果，不各自再算一遍。

**Blocked by:** None

## 为什么必须是单独一票

「上次」「最好」「破纪录」是三个不同口径：

- 上次 = 最近一次做到哪（**会掉**）
- 最好 = 历史最高（**只涨**）
- 破纪录 = 本次超过「本次之前」的最好（**不含本次**）

`isDone` 那次栽的跟头就是这个形状：第一版只判「有没有会话」，于是「开完就结束」（0/9 组）也让卡片写「已经练过」，同一屏的周进度却是 0/3（BACKLOG §14）。三个视图各算一次，迟早再次自相矛盾。

## 要补一个字段：`SetLog.targetType`

`plannedValue` 是裸 `Int`，**45 次和 45 秒长得一模一样**。不补这一列，「上次 45」在平板支撑上会被念成 45 次。

- `SetLog.targetType: SetTargetType?`，`SetLogEntity.targetTypeRaw` 可选列
- 写入点与 `catalogId` 同一处（完成 / 降阶 / 跳过）
- 旧日志 `nil` → 按 `ExerciseLibrary.entry(for:)?.isStatic` 推断：静态算 `durationSec`，其余算 `reps`
- **距离动作（`distance_m`）不进对照**：生成器只产出 `reps` / `durationSec`（`PlanGenerator` 第 193、289、314 行），距离只会从导入的计划进来。给一条没有历史的动作编一个「上次 800 米」是假精确，不如不显示

## 接口

```swift
public struct RecordKey: Hashable, Sendable {
    public var catalogId: String
    public var unit: SetTargetType
}

public struct PersonalRecord: Equatable, Sendable {
    public var last: Int?          // 最近一次（按会话聚合后取最大）
    public var best: Int?          // 历史最高
    public var timesDone: Int      // 做过几节课
    public var lastDate: Date?
    public var bestDate: Date?
}

public enum PersonalRecords {
    public static func build(
        logs: [SetLog],
        before: Date = .distantFuture,
        calendar: Calendar = Calendar(identifier: .gregorian)
    ) -> [RecordKey: PersonalRecord]
}
```

`before` 不是摆设：破纪录判定要问「**本组之前**的最好是多少」，传本组的 `completedAt` 进去就能拿到不含本组的答案，不用在视图里 `filter`。

## 口径（逐条都有测试）

| 情形 | 算不算 | 依据 |
|---|---|---|
| `status == .done` | 算 | 唯一正向证据 |
| `status == .downgraded` | 不算「最好」，但算「上次」 | 降阶的数值低于目标，拿来当纪录是自我安慰；可它确实是他上次做到的量 |
| `status == .skipped` | 不算，整条跳过 | 没做 |
| `origin == .extra` | 算 | 真的做了，只是不进完成率分母（ADR-0006 只说分母，没说这个数不能读） |
| `catalogId == nil` | 不进对照 | 归不到动作。宁可承认缺口，不要假装完整（同 BACKLOG §11 的做法） |
| 同一节课同一动作出现多次 | 取该节课最大值作为「这次」 | 循环组第三次比第一次多，记最大的那个 |
| 目标类型不同 | 分开比，`RecordKey` 里带 `unit` | 45 次与 45 秒不是一件事 |

**去重用 `SessionLedger.distinct`**，与剂量回路同一个出处。不去重的话，一次重复提交就能造出一个假纪录。

## 边界

- 不碰任何视图，不改 `DoseReport`，不新建 SwiftData 表
- 不缓存：数据量是「一个人几年 × 每周几十组」，现算完全够；缓存反而要处理失效
- 不提供「跨动作的总量」：那是剂量，归 `DoseReport`

## 验收

- [ ] `PersonalRecords.build` 是纯函数，不 import SwiftData / SwiftUI，只 import Foundation
- [ ] `RecordKey` 含 `unit`：同一动作的次与秒各算各的
- [ ] 降阶组不进 `best`，但进 `last`
- [ ] 跳过不进任何字段
- [ ] 额外组进 `best`
- [ ] `catalogId == nil` 的日志一条都不出现
- [ ] `before` 传本组时间时，返回的 `best` 不含本组
- [ ] 同一节课两组 10 / 13，返回的「这次」是 13
- [ ] 旧日志（`targetType == nil`）按 `ExerciseLibrary.isStatic` 推断单位
