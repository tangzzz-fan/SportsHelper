# 11: 本地计数——三个月后怎么知道哪条主线有用

**What to build:** 三个本机计数器，不上传、不导出、只给自己看。它不产生用户价值，它决定**这三条主线改完以后，你能不能判断哪条有用**。

**Blocked by:** None（可与任一票并行，建议最先做，成本最低）

## 为什么先做它

现在没有账号、没有埋点，也没有任何「用户拿去干嘛了」的记录。做完 PR 回路与微剂量之后，唯一能回答「有没有用」的证据是：

| 计数 | 回答什么 | 为什么它是硬证据 |
|---|---|---|
| 断点恢复次数 | 他在训练中途离开过几次 | 用户离开 App 的最直接痕迹（BACKLOG §10 已列这条判据） |
| PR 触发次数 | 「比上次强」被说出来过几次 | 除以训练节数 = 每次训练有多少概率听到一句进步 |
| 微剂量使用次数 | 断更那天他有没有打开过 | 这是微剂量唯一的成功判据 |

三个都不需要网络，也都不能用来自我安慰——**分母就摆在旁边**（训练节数、断更天数都是现成的本地数据）。

## 存哪里

`UserDefaults`，不进 SwiftData：

- 不进备份、不进导出、不进计划 JSON
- 不进 `DataResetService` 的 SwiftData 清理事务，但**必须在「清空全部数据」时一起清**（单独一行 `defaults.removePersistentDomain`，漏了会出现「重置后计数还在」）
- key 前缀统一 `dk.counter.`，与通知的 `dk.plan.` 一样，方便一次清干净

```swift
public enum LocalCounter: String, CaseIterable {
    case checkpointResumed
    case recordBroken
    case microDoseStarted
    case microDoseFinished
}
```

四个值而不是三个：微剂量**打开**与**做完**分开计，差值就是「他点了，但没坚持三分钟」——这才是要看的数。

## 怎么看

设置页「关于」里加一行 **「本机记录」**，点开一页只有四行字：

```
断点续练        12 次
破纪录          23 次
三分钟 · 打开    8 次
三分钟 · 做完    5 次
```

- 不做图表、不做百分比、不做「本周」
- 不给用户任何建议文案（「你最近练得少了」这类一律不许）
- 加一行脚注：**「只存在这台手机上，不会上传。」** 这句话必须写，它是这个产品的立场

## 边界

- 不做第三方 SDK、不做崩溃上报、不做 A/B
- 不做「活跃天数」这类能变成运营指标的东西：这份数据只服务于「要不要继续做这条线」，不服务于增长
- 计数失败（写不进 defaults）不报错、不影响主流程

## 验收

- [ ] 四个计数在对应动作发生时各 +1，重复触发不重复计（同一次恢复只计一次）
- [ ] 「清空全部数据」后四个值归零
- [ ] 卸载重装后归零（`UserDefaults` 天然如此，确认没有别处备份）
- [ ] 设置页那页在 Release 构建里也存在（不是 DEBUG-only：用户有权看到自己手机里存了什么）
- [ ] 全仓无网络调用：`grep URLSession` 仍然只有 AI 客户端那一处
