# 08: 预测下一次能多做几个

**What to build:** 一个纯函数，给定某动作的历史与余力，预测他下一次每组能做到多少。**结果不改任何显示的目标值**，只用于 09 落库、10 展示。

**Blocked by:** 01

## 为什么要它

ADR-0005 留了一句可证伪的话：

> 判断「App 是否更懂我」的唯一判据是**预测误差在缩小**：周一预测的每组次数与周末实际完成之差，逐周收窄才叫懂；不收窄说明它只是在套规则。

`plannedValue` 与 `actualValue` 已经配对落库，但**从来没有一个预测值**，所以这句话到今天都没法验证。

## 规则（只有一条，故意简单）

```
预测 = 上次最好的一组
     + （该动作最近一次自评余力 rpe ≤ 2 ? 1 : 0）
     封顶：计次动作 15（repCeiling），静态动作 60 秒（保持时间上限）
```

三条约束：

1. **只看历史，不看计划目标**。拿计划目标当预测，会把计划的错算成用户的错——那正是这套回路要消灭的东西
2. **余力只在「最后一组」采信**。中间组的余力已经被 15 号票排除（BACKLOG §15），这里沿用同一口径，不另开规则
3. **不加就不加**：余力缺失（`nil`）、余力为 3–5、上次是跳过——一律只取上次最好，不猜

```swift
public enum Prediction {
    public static func next(
        for key: RecordKey,
        from record: PersonalRecord,
        lastRPE: Int?
    ) -> Int?
}
```

返回值是**建议值**，不是目标值。它不进 `WorkoutPrescription`、不进 `SetTarget`、不进播报。

## 与「采纳」的关系（容易踩线）

预测看起来像「App 自己把数字改了」。它不是：

| | 预测 | 加量提案 |
|---|---|---|
| 改动什么 | 什么都不改 | 改 `WorkoutPlan` |
| 生效条件 | 无（只是个数） | 用户点「就这样」（ADR-0004） |
| 用户在哪看到 | 记录页那条曲线（10） | 计划页的提案卡 |

**任何把预测值直接显示成训练目标的实现都是错的**，那就是绕过 ADR-0004。这条要写进注释式测试名里（`doesNotTouchPlanTargets`）。

## 边界

- 不做机器学习、不做周期化、不做 ACWR、不读心率
- 不做「预测今天状态不好所以减量」——那是替用户判断身体，ADR-0005 只允许能力进公式
- 距离动作不预测（单位不可靠，理由同 01）

## 验收

- [ ] 无历史 → `nil`（不预测第一次）
- [ ] 上次最好 12、余力 `rpe = 2` → 13
- [ ] 上次最好 12、余力 `rpe = 3` → 12（有余力但不够，不猜）
- [ ] 上次最好 12、余力 `nil` → 12
- [ ] 计次动作到 15 封顶，不再 +1
- [ ] 静态动作 +1 秒还是 +5 秒要与 `DoseAdjustment` 的保持时间轴一致（现在是 +5 秒、上限 60），**不允许两套**
- [ ] 预测值不改任何 `WorkoutPlan` 里的 `SetTarget`
