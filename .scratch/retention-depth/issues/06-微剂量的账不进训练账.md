# 06: 微剂量的账不进训练账

**What to build:** 微剂量做完要留痕，但**一个训练口径的数字都不能动**。先把存储与隔离定死，再谈入口（07）。

**Blocked by:** 05

## 为什么顺序不能反

先做页面、后补口径，就会出现「练完了，完成率也变了」这种返工。剂量回路那次已经吃过一次：`SetLog` 少了 `catalogId`，肌群分布永远算不出来，只能回头补列（BACKLOG §11）。

微剂量的口径在 `GLOSSARY.md` 里已经写死：

> 休息日给出的一个三分钟以内的单动作，用来让习惯不断档。它**不算一次训练**，不进完成率，也不做连续打卡。

现在把它落成结构。

## 存储：独立一张表

```swift
@Model final class MicroDoseEntity {
    @Attribute(.unique) var id: UUID
    var date: Date          // 完成那一刻
    var catalogId: String
    var seconds: Int        // 实际总时长（160 或提前结束）
    var completed: Bool     // 三组都做完了没有
}
```

**不进 `SetLog`。** 理由不是洁癖：`SessionLedger` 按 `SetLog.origin` 分账，多一个 `.micro` 会让 `DoseReport`、`isEffective`、完成率分母三处同时要加分支；而它们的分母口径是相对同类 App 唯一的硬差异点（ADR-0006），不值得为三分钟的事去动。

## 隔离清单（每一条都要有测试）

| 数字 | 出处 | 做完微剂量后 |
|---|---|---|
| 完成率 | `SessionLedger` → `SessionRecap` | 不变 |
| 本周 x / y | `HistoryStats.completedDaysThisWeek` | 不变 |
| 连续天数 | `HistoryStats.streak` | 不变 |
| 有效组 | `DoseReport.effectiveSets` | 不变 |
| 训练节数 | `SessionEntity` 计数 | 不变 |

**连续天数不变是刻意的。** 「断更那天至少动了一下」值得被记住，但不该让 streak 续上——streak 的定义是「有训练的日子」，改了这个定义，`isDone`、周进度、结束页三处都会跟着要改。

## 与计划的关系

- 不产生提案，不触发 `revision`
- 不改今天的 `dayIndex` 归属：休息日做完微剂量，今天仍然是休息日，「这一节练过没有」仍然是「没有」
- 不写 `WorkoutCheckpoint`：三分钟不需要断点续做

## 边界

- 不做补偿：提前结束就是提前结束，不记录「还差几秒」
- 不导出：它不进计划 JSON，也不进任何备份
- 清空全部数据时一起清（`DataResetService` 要加这一张表，漏了会出现「重置后还显示昨天动过」）

## 验收

- [ ] 做完一次微剂量，上表五个数字逐字段不变（快照测试：同一份日志，喂不喂微剂量记录，`DoseReport` 相等）
- [ ] `MicroDoseEntity` 不出现在 `SessionEntity` 的任何查询里
- [ ] `DataResetService` 清空后该表为空
- [ ] 旧存档升级不会崩（新表由 SwiftData 自动建，不写迁移代码）
