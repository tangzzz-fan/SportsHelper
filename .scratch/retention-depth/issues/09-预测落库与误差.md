# 09: 预测落库与误差

**What to build:** 训练时把预测值写进那条 `SetLog`，事后才能算「我猜的」与「他做的」差多少。规则会变，落库的值不能变。

**Blocked by:** 08

## 为什么要落库，不能事后重算

事后用当前规则去重算历史预测，等于**用改正后的答案去批改当时的卷子**：规则一改，过去所有误差一起变，曲线永远好看。

所以预测必须在**这一组开始之前**定下来，跟着日志一起落盘。

```swift
// SetLog 新增
public var predictedValue: Int?        // 训练前算好的预测
// SetLogEntity
var predictedValueRaw: Int?
```

写入点与 `catalogId` / `targetType` 同三处（完成 / 降阶 / 跳过）：

| 状态 | 写预测值 | 算误差 |
|---|---|---|
| `done` | 写 | 算 |
| `downgraded` | 写 | **不算**：降阶的目标已经被压低，`actual` 低于预测是规则造成的，不是判错的证据 |
| `skipped` | 写（如果当时算过） | **不算**：没做就没有对照 |

## 误差怎么算

只用一个数：**平均绝对误差（MAE）**，按周聚合。

```
本周误差 = mean( |predicted − actual| )，仅 done 组
```

- 不用百分比：`12 → 10` 是差 2 个还是差 17%，前者是人话，后者像考试
- 不用带符号误差：他多做少做都算「猜不准」，不区分方向（方向由加量/减量规则去管，不在这里）
- 分母是**参与计算的组数**，不是全部组数。跳过与降阶要明说被排除了，否则用户会觉得「怎么才算了这么几组」

## 与既有口径的关系

| 已存在的东西 | 与预测的关系 |
|---|---|
| `plannedValue` | 计划说做几个 |
| `actualValue` | 他做了几个 |
| `predictedValue` | 系统猜他做几个 |

**三者互不覆盖。** `plannedValue` 是处方（改动要采纳），`predictedValue` 是估计（随时可变），`actualValue` 是事实。把 `predicted` 写进 `planned` 是最容易犯的错，`doesNotOverwritePlannedValue` 要有测试。

## 边界

- 不改完成率、不改剂量、不产生提案
- 旧日志没有这一列 → 不进误差统计，也不补算（补算就是事后批卷）
- 不导出到计划 JSON：它不是计划的一部分

## 验收

- [ ] 完成一组：`predictedValue` 非空，且等于训练开始前算出来的那个值（不是完成后再算）
- [ ] 降阶：写了 `predictedValue`，但周误差的分母不含它
- [ ] 跳过：不进误差
- [ ] 旧日志（`nil`）：`DoseReport` 的数字一个都不变
- [ ] `plannedValue` 在完成一组前后完全一致
- [ ] 同一周喂同一批日志，算两次误差结果相同（纯函数）
