# 04: 周报只报进步

**What to build:** 记录页顶部一行「这周 3 个动作破了纪录」。把周报从「打卡统计」变成「进步统计」。

**Blocked by:** 01, 03

## 为什么不能塞进 `DoseReport`

`DoseReport` 的口径是**剂量**：有效组、肌群分布、跳过原因。它回答「练了多少」，而且它的数字会被 ADR-0006 的分账规则约束（额外组不进完成率分母）。

「破了几个纪录」是另一套口径：按动作、按历史、不看肌群。塞进 `DoseReport` 会让那个结构变成两个不相干的答案拼在一起，而且以后任何改剂量的票都得绕开这一节。

新建 `WeekHighlights`，纯函数，输入 `[SetLog]` + 周起点：

```swift
public struct WeekHighlights: Equatable, Sendable {
    public var recordsBroken: Int
    public var actions: [String]      // 破纪录的动作名，用于「深蹲、俯卧撑…」展开
}

public enum WeekHighlightsBuilder {
    public static func build(logs: [SetLog], now: Date, calendar: Calendar) -> WeekHighlights
}
```

判定：本周内某组 `done` 且超过 **本周之前** 的最好。一周内同一动作破多次，只算一个动作。

## 展示

- 位置：记录页顶部三数（本周有效组 / 训练天 / 连续）下方，一行
- 文案：**「这周 3 个动作破了纪录」**，动作名可列两个：**「深蹲、俯卧撑」**
- 为 0 时**整行不出现**。0 不是消息，写「本周暂无新纪录」等于提醒他退步了
- 不做百分比、不做「超过了 80% 的用户」——没有账号，也没有同类数据，编不出来

## 边界

- 只统计本周，不做累计总数（累计数只会越滚越大，第六周就没感觉了）
- 不做「连续 N 周都有纪录」的连续计数——那是 streak 的变体，会把好事变成压力
- 不进通知、不进小组件（要做是另一个决定，得单开 ADR）

## 验收

- [ ] 本周破 2 次、涉及 1 个动作：显示「这周 1 个动作破了纪录」
- [ ] 上周破的纪录不算进本周
- [ ] 0 条时不出现这一行，记录页高度与改之前一致
- [ ] 旧日志（无 `catalogId`）不参与，也不影响计数
- [ ] 与 `DoseReport` 的四个数字互不干扰（同一份日志喂两个 builder，各算各的）
