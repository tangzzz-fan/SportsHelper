# 留存深度：让 App 有记性

三条流失断点里，第二个是主战场：**用户练到第八天，手里只有「完成率 100%」，没有「我比上次多做了几个」。**

打卡靠意志，变强靠证据。这份文档把「给 App 装记性」拆成十一张票。

- 原则：ADR-0004「计划只因用户选择而变」、ADR-0005「个体化只调变量不调目标」、ADR-0007「播报只允许封闭词表」
- 词表：`GLOSSARY.md` 的「剂量」「有效组」「余力」「微剂量」
- 前置阅读：`docs/FLOW.md` §3（执行链）、`docs/specs/BACKLOG.md` §10（为什么先不做呈现层）、§11（记录页的口径）

## 现状：记性在哪一段断掉

数据是全的，出口是空的。

| 已经有 | 位置 | 从来没被用过 |
|---|---|---|
| 每组的目标值与实际值 | `SetLog.plannedValue` / `actualValue` | 只用来判「是不是多做了」（剂量回路） |
| 每条日志挂着哪个动作 | `SetLog.catalogId`（可选） | 只用来算肌群剂量 |
| 跳过原因、自评余力 | `skipReason` / `rpe` | 只进减量分支与有效组判定 |
| 每周肌群组数、四周柱 | `DoseReport` | 只回答「练了多少」 |

`grep -rE "上次|lastTime|personalBest"` 在 `DongKe/ DongKeCore/` 只命中三处，全是导入纠正的文案，**训练页一次都没有**。

**这不是缺功能，是账本没回读。** 剂量回路把记录接到「要不要改计划」上，但没接到「你比上次强了多少」上——前者一周说一次，后者每次训练都该说。

## 三条主线

```
01 历史对照的唯一出处 ──┬─> 02 组前一行 ──> 03 破纪录当场 ──> 04 周报只报进步
                        │
                        └─> 08 预测规则 ──> 09 预测落库 ──> 10 校准曲线

05 微剂量选哪个动作 ──> 06 账不进训练账 ──> 07 休息日那个三分钟入口

11 本地计数（独立，可与任一票并行）
```

**主线 A（01–04）是挽留第八天的人。** 01 打通数据，02 是 tracer bullet——一行字就能验证整条链路通不通；03 让「变强」当场发生；04 把它汇总成一周一次的证据。

**主线 B（05–07）是挽留第二十一 天的人。** 那天的人不想变强，只想「今天真的没时间」。给他一个三分钟出口，「停止」才会变成「降级」。

**主线 C（08–10）是 ADR-0005 留下的空头支票。** 「预测误差在收窄才叫懂你」写进了 ADR，`plannedValue` 与 `actualValue` 也配对落库了，但没有一处算过这个差。它最晚做，因为它依赖 A 的对照能力。

## 一张票为什么这样切

**01 必须单独一票。** 「上次」「最好」「破纪录」是三个不同口径，散落在三个视图里各算一次，迟早互相打架——`isDone` 那次就是栽在「有没有会话」和「全部组完成」的差别上（BACKLOG §14）。口径只有一个出处，视图只做排版。

**02 是 tracer bullet，先于 03。** 一行「上次 10 · 最好 12」跑通，说明 `SetLog → 查询 → 注入训练页` 这条路是通的；跑不通，03 的破纪录判定也一定是假的。先看见再加规则。

**03 与 04 分开，因为「当场」和「一周」是两种心情。** 03 是组间那三秒，用户还喘着，只能给一句话加一次触觉；04 是周日晚上翻记录，可以给一句总结。合成一票会逼着一个视图同时服务两种节奏。

**06 卡在 05 和 07 之间，是刻意的。** 「微剂量不算一次训练」这条口径必须先落成存储结构，再谈入口。反过来做（先做页面，再把口径补上）就会出现「练完了，完成率也变了」这种返工。

**08 与 09 分开，因为规则会变、数据不该跟着变。** 预测规则只有一条（上次最好 + 余力），将来一定会改；`predictedValue` 一旦落库就不能回头改。所以规则单独可测，落库单独一票。

**11 不阻塞任何票，但决定后面怎么验证。** 没有账号、没有埋点，这三条主线改完，唯一能证明有用的就是本机计数器。它成本最低，收益在「三个月后你还能不能判断哪条主线有效」。

## 口径：什么算纪录

一张表定死，01 里的守卫逐条钉住：

| 情形 | 算不算「最好」 | 理由 |
|---|---|---|
| `status == .done` 且 `actualValue` 高于历史最好 | 算 | 唯一正向证据 |
| `status == .downgraded` | 不算 | 降阶的数值低于目标，拿来当纪录会自我安慰 |
| `status == .skipped` | 不算 | 没做 |
| 额外组（`origin == .extra`） | 算 | 用户真的做了，只是不进完成率分母 |
| 旧日志没有 `catalogId` | 不进对照 | 归不到动作，宁可承认缺口（同 BACKLOG §11 的做法） |
| 同一节课里同一动作出现多次 | 取该节课最大值作为「这次」 | 循环组里第三次比第一次多，记最大的那个 |
| 目标类型不同的记录（次 vs 秒） | 分开比，不跨类 | 45 次与 45 秒不是一件事 |
| 距离动作（`distance_m`） | 暂不进对照 | 主项里没有这类动作；导入的若出现，不要造一个假纪录 |

**「上次」与「最好」是两个东西**：上次问「最近一次做到哪」，最好问「历史最高是多少」。前者会掉，后者只涨。掉的时候文案按前者，庆祝按后者。

## 不做什么

| 不做 | 理由 |
|---|---|
| 播报「上次 10 个」 | ADR-0007：一拍一句、单句 ≤4 秒，塞进去必然截断或飘音。**PR 只走视觉** |
| 总榜 / 排名 / 连续天数加码 | 与「无账号、单机」冲突，且把进步做成社交压力 |
| 推送提醒「你三天没练了」 | ADR-0003 / ADR-0004 的立场：不做主动劝告 |
| 拿预测去改训练页的目标值 | 那是计划变更，必须先「采纳」（ADR-0004）。预测只落库、只展示 |
| 跟练分路（五禽戏一类） | `.scratch/follow-along/issues/01` 已论证：这是**换一批用户**，不是给现有用户加深 |
| 小组件 / 灵动岛 / Watch | BACKLOG §10 已排优先级：呈现层，计划还没有记性之前做包装是本末倒置 |
| HealthKit / 自动识别动作 | 同上，且引入权限与不可靠信号 |

## 怎么算这条线成功了

**短期（A 线落地后一个月）**：11 的计数器里，`PR 触发次数 / 训练节数` > 0.3 —— 每三节课至少有一次「比上次强」被说出来。低于 0.3 说明阈值太严或者对照算错了，不是用户不进步。

**中期（B 线落地后）**：`微剂量使用次数 / 断更天数` 大于 0 —— 断更那天他至少打开了一次。这条不需要很大，只要不为零。

**长期（C 线）**：预测误差逐周收窄。不收窄就说明规则只是在套公式，ADR-0005 那句话得改。

**这些数字都必须本地算**，不上报。设置页只给用户看「记录」两个字的东西，不做百分比仪表盘——那是给产品看的，不是给用户看的。

## 开工顺序

`11`（可与任一票并行）→ `01` → `02` → `03` → `04` → `05` → `06` → `07` → `08` → `09` → `10`

02 做完就该上模拟器手动走一遍：练两个动作 → 看训练页有没有那行字 → 重进 App 再看一次（验证不是内存里临时算的）。
