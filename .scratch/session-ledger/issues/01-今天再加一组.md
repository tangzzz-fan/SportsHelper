# 01: 今天再加一组——入口、流程插入与断点续练

**What to build:** 用户做完某个动作的最后一组，觉得还有余力，可以当场给这个动作再加一组。这一组落成 `origin = .extra` 的日志，进剂量、不进完成率，也不让「这一节练过没有」成立。

**Blocked by:** None（账本与来源字段已落，ADR-0006）

**状态（2026-10-25）：代码已落地。** 脚本插入、额外组来源、跳过不落日志、断点存脚本、最多 3 组、撤销都已接上；单测覆盖脚本与 checkpoint。休息页按钮的点击链路与真机旧库迁移待手动走一遍。

## 入口放在哪

- 只在**当前动作的最后一组完成后的休息页**出现，按钮文案「今天再加一组」；不在任意时刻、任意动作上出现。
- 点击后不直接记一组，而是把这一组排进当前动作之后：按钮变成「已加一组，休息完继续」，给一次撤销。
- 一节课最多加 **3 组**（防止把「再加一组」当成分页按钮）。到顶后按钮消失，不解释。

## 流程怎么插

`WorkoutFlowModel` 是 `let`，不要改成可变。`WorkoutSession` 另持一份可变的 `script: [FlowStep]`（初始化为 `flow.steps`），加组时在 `stepIndex + 1` 插入：

```swift
.set(prescriptionId: id, setIndex: nextExtraIndex, target: target, restAfterSec: restAfterSec)
```

- `nextExtraIndex` = 该动作已落日志的最大 `setIndex` + 1，不从 `flow.setCounts` 推——休息页可能同时存在多个额外组。
- 显示仍是「第 4 组 / 共 3 组」：`currentSetTotal` 用 `flow.setCounts[id] + 已在 script 里排队的该动作额外组数`，别让用户看到「第 4 组 / 共 3 组」这种自相矛盾。
- `plannedSets` 永远取 `flow.plannedSets`，不从 `script` 数。

## 断点续练（这张票的重点）

`WorkoutCheckpoint` 现在只存 `stepIndex` + `logs`。如果 `script` 插过额外组，重建时会比 `stepIndex` 短，导致跳过计划组或直接到 `.finished`。

二选一，推荐前者：

1. **checkpoint 存额外组的插入位置**：`extraSteps: [ExtraStep]`，每条 `{ afterStepIndex, prescriptionId, setIndex, targetValue, restAfterSec }`。恢复时先按 `flow.steps` 建基线，再按 `afterStepIndex` 升序插回去；`totalSteps` 用重建后的 `script.count`。
2. **从 logs 反推**：按 `completedAt` 顺序把 `origin == .extra` 的日志插到对应计划组之后。不需要新字段，但要求日志的时间顺序严格可靠，且额外组未完成时无法恢复。

`WorkoutResumePolicy.canResume` 的 `stepIndex < totalSteps` 判定要改成对重建后的 `script` 判定。

## 记账

- 落盘：`SetLog(origin: .extra, setIndex: nextExtraIndex, plannedValue: target.value, ...)`。
- `SessionLedger.extraSets` 自动 +1；`completedSets` 不变。
- `SessionEntity.completedSets` 仍存计划内完成数；不要为了显示把额外组加进去。
- 结束页「本周 x/y」不受影响。

## 验收

- [x] 完成额外组：`SetLog.origin == .extra`，`SessionLedger.extraSets == 1`，`completedSets` 不变
- [x] 跳过额外组：不落日志（`extraSets` 与 `skips` 都不计）
- [x] 跳过计划组 + 加做两组：完成率仍 < 100%，`HistoryStats.isCompleted == false`
- [x] 一节课加满 3 组后不能再加（`canAddExtraSet` 用完成数封顶）
- [x] `SessionLedgerTests` / `ExtraSetFlowTests` / `SessionRecapTests` / `HistoryStatsTests` 全绿
- [ ] 最后一组后休息页出现「今天再加一组」，点击后休息计时不中断（待手动）
- [ ] 加组后当前组序号连续，组总数不出现「4 / 3」（待手动）
- [ ] 加组后立刻杀进程，30 分钟内续练：`stepIndex` 指向正确，不跳计划组（脚本往返已测，App 层待手动）

## 刻意不做

- 不给「补昨天欠的组」：那是排期偏移（BACKLOG §14）。
- 不在动作已经切走之后回头加组：入口只认当前动作。
- 不把额外组写回计划（ADR-0004）。
