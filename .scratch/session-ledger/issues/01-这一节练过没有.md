# 01: 这一节练过没有——给会话补上「它兑现的是哪一天」

**What to build:** 一次训练在数据库里只知道「我叫下肢力量、做了 12/15 组、发生在周日下午」，**不知道它兑现的是哪一节计划**。补上这个对应关系，三个表面缺陷同时消失：提前练能选对日、训练日不会被重复催、结束页能说出本周到哪儿。

**Blocked by:** None

## 两个已经暴露的错

1. **卡片写周三，点下去开的是周一。** 休息日卡片显示 `nextTrainingDay`，`AppShell.startWorkout` 却取 `plan.days.first(where: { !$0.isRestDay })` = 本周第一个训练日。周二休息（计划一三五）时两者必然不一致；只有「休息日正好是第一个训练日前一天」才碰巧对上。
2. **同一节课可以算两次。** 到真正的训练日，Today 仍旧「开始训练」；再练一次，本周进度 +1。

## 关键取舍：周目标按计划日算，不按日历天

`planDate` 一加，周进度就多了一种算法。**选了「按计划日归属」**：周日提前练下周一的课 → 记在**下周一那一周**，周一切过去就是 1/3；本周仍 0/3（本周那三节确实没练）。

否掉另一个选项（记在周日那周）的理由很硬：它会让周一同时出现「这一节已经练过」和「本周 0/3」——界面上自相矛盾。宁可周日那一瞬间的数字诚实一点。

## 怎么算「今天该练哪一节」

`PlanCalendar.occurrence(on:in:)`：今天是训练日 → 今天；否则往后找第一个训练日（最多 7 天，可跨周）。

**卡片和按钮都用它。** 这一条是整张票的重点：以前是两套算法各算一次，所以必然有一天对不上。

深链和续练用 `occurrence(of:anchoredAt:in:)`：在那一天前后各三天的窗口里找它这一周的位置。窗口正好 7 天，任何星期都会命中且只命中一次，不需要猜。

## 已知缺口

- **三处文案没有自动化兜底。** UI 测试已按规矩全删；「已练过」与「本周 x/y」两种状态在周日模拟器上看不到（那天是休息日），**没截图**。
- **没做完的会话不算「练过」。** `isDone` 要求全部组完成，所以做了 8/9 组的人第二天仍会看到「开始训练」；没做完的会话靠「上次训练没做完」的续练卡兜着。要不要改成「练了八成就算」，等真机数据。
- **跳过（今天不练）与提前练的关系还没定。** 现在跳过只影响周目标的分母，不影响 `planDate`：跳过周一、周三照练，周一那节就空着。要不要在周末提示「本周还欠一节」，那是另一张票。
- **同一天练两节算两节。** `completedDaysThisWeek` 数的是不同的 `planDate`，所以一天里先练今天的、再补欠下的，会 +2。这比按日历天更准，但卡片上「本周 2/3」可能让人以为自己练了两天——文案暂时没解释（已记 BACKLOG §14）。
