# 06: 神经引擎试点（有门槛，过不了就停）

**What to build:** 在 iPhone 上验证一个「许可干净 + 实时 + 体积可接受」的中文神经 TTS。

**Blocked by:** 02, 03, 04

**Status:** parked（2026-10-25，被音条线取代）

> 音条方案（`.scratch/coach-voice/`）走的是**离线渲染 + 运行时拼接**，绕开了 RTF、体积与设备内推理。
> 它一旦成立，本票要解决的问题（系统音色僵硬）就不存在了。所以 06 不再是 07 的前置：
> 只有当音条被判死（拼接感不能接受），才回来做这一票。见 ADR-0007「播报里不得出现自由文本」。

## 门槛（ADR-0007）

三条同时成立才继续，缺一条就停在 `04` 的系统音色：

1. **商用许可干净**：运行时、模型权重、G2P 依赖三者都能闭源分发。
2. **实时**：iPhone 16 Pro 上 RTF < 0.5，首音延迟 < 300ms。
3. **体积**：随包 ≤30MB，或按需下载 ≤200MB。

## 候选（2026-10-25 核查）

| 模型 | 许可 | 体积 / 采样率 | 实时性 | 判定 |
|---|---|---|---|---|
| `matcha-icefall-zh-baker` | **非商用**（DataBaker 语料，官方 Caution） | 165MB / 22.05k | RPi4 RTF 0.41 | 排除 |
| `vits-icefall-zh-aishell3` | Apache-2.0 | 29MB / **8kHz** | RPi4 RTF 0.16 | 许可过、音质不赚 |
| `vits-melo-tts-zh_en` | MIT（MeloTTS） | 163MB / 44.1k | RPi4 RTF 2.52 | **唯一值得实测** |
| Kokoro multi-lang | 权重 Apache-2.0，中文 G2P 依赖 eSpeak-NG **GPL-3.0** | 88–310MB | iPad RTF 1.5–1.8 | 排除（许可 + 慢） |
| Piper `zh_CN-huayan` | 仓库未声明，上游为非商用音色 | 63MB | RTF < 1 | 排除 |

运行时统一用 **sherpa-onnx**（Apache-2.0，官方 Swift API + iOS SwiftUI 示例 + SPM/XCFramework）。

## 步骤

- [ ] Spike：SPM 引入 sherpa-onnx，跑 MeloTTS zh_en，用 `scripts/voice-dump.sh` 的 20 条真实文案测：首音延迟、RTF、峰值内存、包体增量。
- [ ] 许可复核：MeloTTS 权重与训练数据（AISHELL-3 / 其它）的再分发条款，落一段结论进 ADR（不放过「未声明」）。
- [ ] 过门槛才做投递：`SpeechAvailability.needsDownload` + 下载页（Wi-Fi 提示、进度、取消、失败回落系统音色）。
- [ ] `SpeechRouter` 按「设置 + availability」选引擎，系统音色永远是兜底（ADR-0001）。
- [ ] 未过门槛：写 ADR 修订，说明测得的具体数字，停在系统音色；不硬上。

## 验收

一页实测报告（机型 / 模型 / 首音 / RTF / 内存 / 包体 / 许可结论），进 `.scratch/audio-audit/`。

## 不做

- 不做声音克隆（CosyVoice / F5 / IndexTTS 这类 0.5B+ 模型，iPhone 内存和首音都不合格）。
- 不做云端 TTS（违背离线承诺）。
- 不为换引擎而改 Core 的文案逻辑——`02` 之后引擎只在适配器层。
