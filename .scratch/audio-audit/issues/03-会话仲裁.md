# 03: 会话仲裁

**What to build:** `AVAudioSession` 只有一个 owner，播报与收音都向它借。

**Blocked by:** 02

**Status:** done（2026-10-25）

## 现状

`SystemSpeechAnnouncer.activateSession/deactivateSession` 与 `SystemSpeechTranscriber` 各写一遍，直接操作同一个 `AVAudioSession.sharedInstance()`。今天不出错是因为「播报在训练页、收音在导入页」，不是因为有所有权。

另有一处高风险：播报**每念完一句**就 `setActive(false)`，而队列里可能还有下一句（倒数 3/2/1 各是一句）。真机待验，若确实会掐断，倒数会变成跳号。

## 改动

- [ ] `DongKeCore` 新增纯值类型 `AudioSessionLease`（引用计数逻辑，可单测）：`borrow(mode)` / `release`。
- [ ] `DongKe/Services/AudioSessionArbiter.swift`：真正调 `AVAudioSession`，只在 refCount 从 0→1 时 `setActive(true)`，从 1→0 时 `setActive(false, .notifyOthersOnDeactivation)`。
- [ ] `SystemSpeechRenderer` 借 `.ambient` 租约，**整段播报期间持有**，最后一句 `finished` 才释放（不是每句）。
- [ ] `SystemSpeechTranscriber` 借 `.record` 租约，`stop/cancel` 释放。
- [ ] 两个 mode 不同：仲裁器按「最高需求」设 category，释放后回落。

## 验收

- 单测：两次 `borrow` 一次 `release` 后仍 active；两次 `release` 后 inactive 且只调一次 deactivate。
- 真机：训练中播完一句后音乐不停顿（现在每句都断一次）。
- 真机：倒数 3/2/1 三句连着念，不跳号、不出现半句。

## 不做

- 不申请后台音频（AC-24「仅前台」不变）。
- 不做 ducking：`.ambient` 下 duck 不生效，改 `.playback` 会丢静音键语义。
