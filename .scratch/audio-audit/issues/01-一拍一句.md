# 01: 一拍一句

**What to build:** 休息归零只说一句，动作中只说两句。

**Blocked by:** 无

**Status:** done（2026-10-25）

## 现状

`WorkoutSession.refresh()` 在同一轮里先 `voice.restFinished(...)`（4.23s）再 `advance()` → `voice.stepChanged(...)`（3.75–4.80s）。实测两句都完整播出，合计 **8.79 秒**；第二句说完时用户已在做第 1 组 8.8 秒。

## 改动

- [ ] `WorkoutVoiceSession.restFinished(nextStepIndex:)`：若下一条是 `.set`，**一句都不说**，交给 `stepChanged` 说；只有没有下一组时才念「休息结束」。
- [ ] `WorkoutAnnouncementBuilder` 的 `.setStart` 删 `nextName`（预告归休息页与 `restStart`，组中不说「下一个」）。
- [ ] 删 `WorkoutPromptPlanner` 的 `.timeUp`（计时归零已由 `Haptics.setTimeUp` 的系统音 + 触觉表达，再念「时间到」是四声重复）。
- [ ] 删 `WorkoutVoiceSession.allowsEncouragement` 与 `.encourage`（从未被置 true，死代码）。
- [ ] `textLimit` 40 字 → **13 字（≈3 秒）**；`compose` 的丢弃顺序不变：先丢「共 N 组」，再丢预告，动作名与剂量最后动。

## 验收

- 新单测：休息归零后只出现一条 `setStart`，`spoken.count == 1`。
- 新单测：`setStart` 文案字数 ≤13 且包含动作名与剂量。
- 新单测：静态动作一组只出两条语音（中段要点 + 「3」），归零后无 `.timeUp`。
- `scripts/voice-dump.sh` 三种计划形态重跑，序列里不再有「休息结束」紧跟「第 N 组」。

## 不做

- 不改 UI 上的「第 N 组 / 共 M 组」——两边共用 `WorkoutFlowModel` 口径，界面不受影响。
- 不动「开始训练」「完成」两句的文案。
