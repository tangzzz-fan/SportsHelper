# 05: prompt 区块取词约束与复测

**What to build:** 在系统提示词里把三个区块的取词范围钉死，然后重新采样确认库外动作降到可接受水平。

**Blocked by:** 02, 03, 04

**Status:** done（2026-10-24）

## 条目

- [ ] `AIPromptBuilder.systemPrompt` 增加区块规则：
  - `warmup` 只能取 `purposes` 含 `.warmup` 的动作，2–3 个，每个 30–60 秒
  - `main` 取 `.strength`，组数按水平与目标给，同一动作一天最多出现一次
  - `cooldown` 只能取 `purposes` 含 `.stretch` 的动作，2–3 个，每个 30 秒
- [ ] prompt 里的动作清单由 `catalogIds` 扩成「id + 名字 + 用途」，让模型看得见哪些能放热身
- [ ] 保留现有硬性要求（7 天、枚举值、`custom_` 前缀），不推翻
- [ ] 复测脚本留在 `/tmp` 即可，不进仓库；采样 8 场景，统计库外比例

## 验收标准

| 指标 | 目标 |
|---|---|
| 库外动作比例 | ≤ 3%（现在 23%） |
| `warmup` 区块出现库外动作 | 0 次 |
| `cooldown` 区块出现库外动作 | 0 次 |
| `cooldown` 里出现训练动作（死虫、侧平板） | 0 次 |

## 已知风险

模型对「只能取 X 类」的遵守率不是 100%。如果复测达不到 3%，加一层本地兜底：解析后扫一遍区块，`cooldown` 里凡是 `purposes` 不含 `.stretch` 的条目剔除或换成库内拉伸动作——但这一层要单开 ticket，不塞进本票。
