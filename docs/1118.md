# 动刻产品深化方案（文档计划）

## 产出

- 在 [docs/specs/BACKLOG.md](docs/specs/BACKLOG.md) 末尾加 §17，用一段指针指向新文档，保持 BACKLOG 作为索引

## 核心判断（文档第 0 节）

执行这一段已经做得很深：剂量回路、个人纪录、微剂量、预测校准都已落地。但执行留下的证据只流到两个地方：一是 App 自己的提案，而提案只对自有计划主动出现；二是用户自己看的纪录和周报。它还没流到用户在意的另外三处：

1. **用户信任的计划来源**（ChatGPT 或教练）
2. **真实的负重**
3. **当天的实际情况**

所以文档提三条主线：**回流、记准、弹性**。

## 第 1 节：三处结构性断点（每条按"场景 → 代码证据 → 后果"写）

### 1.1 主画像用不上最深的那条回路

- **场景**：用户拿着 ChatGPT 的计划，到了第三周。
- **证据一**：外来计划不会主动收到提案（ADR-0003）。
- **证据二**：[DongKeCore/AI/AIPromptBuilder.swift](DongKeCore/AI/AIPromptBuilder.swift) 的 `userBrief` 只放档案和用户原话，**不带任何执行记录**。
- **证据三**：外来计划点"调整"，走的是 [DongKe/Features/Plan/PlanAdjustView.swift](DongKe/Features/Plan/PlanAdjustView.swift) 的 `PlanGenerator.makePlan(...).markingSource(.generated)`，也就是**用本地生成的计划把用户导入的那份换掉**。
- **证据四**：全仓没有导出或分享入口。
- **后果**：PRD 洞察二说的"AI 不知道他上周漏了两次"，在 AI 这条路上原样存在。

### 1.2 账本只记次数，不记重量

- **场景**：主画像有 5–20kg 的可调哑铃。
- **证据一**：`SetLog` 没有负重字段。
- **证据二**：`PersonalRecords` 只比较 `actualValue`。
- **证据三**：[DongKeCore/Workout/DoseAdjustment+Progression.swift](DongKeCore/Workout/DoseAdjustment+Progression.swift) 里加负重的算法是 `(load * amplitude * 10).rounded() / 10`，8kg 会被建议加到 8.8kg，这个重量买不到。
- **后果**：用户自己换了更重的哑铃、次数变少，会被记成退步，"上次 · 最好"那一行也会误导人。

### 1.3 计划按周固定，生活按天变化

- **场景**：会议拖了，今天只剩 15 分钟；或者练到一半被拉进一个一小时的会。
- **证据：现有的弹性工具只有这些**
  - "今天不练"
  - 提前练
  - 微剂量（`MicroDosePlanner`，只在休息日出现）
  - 断点续练（`WorkoutCheckpoint.window = 30 * 60`，只有 30 分钟）
  - 训练中的减半次数、跳过本组、休息加 30 秒
- **缺的**：
  - 训练日当天把这一节缩短
  - 训练中换一个动作（PRD 里 F12 是 P1 第一顺位，至今没做）
  - 提醒时刻永远固定，`ReminderHealth` 只检查权限和条数
- **后果**：训练日只有"全做"和"不做"两种选择。"没时间"连续跳过三次后，系统会砍掉一个动作，等于把当天的一次性情况当成了计划本身的问题。**这同时也在污染剂量回路的信号。**

## 第 2–4 节：三条主线

```mermaid
flowchart LR
    Logs["执行记录 SetLog"] --> Receipt["训练回执"]
    Receipt --> Source["用户信任的来源 ChatGPT或教练"]
    Source --> NewPlan["新版本计划"]
    NewPlan --> Diff["版本对比校对页"]
    Diff -->|"用户保存"| Plan["计划下一版"]
    Plan --> Logs
```

### A 回流：把执行证据还给计划的来源

- **A1 训练回执**：在 Core 里加一个纯函数，汇总最近 N 周的执行情况，包括：
  - 每个动作计划做多少、实际做了多少，以及重量
  - 降阶和跳过的原因
  - 余力、疼痛标记
  - 个人纪录、漏练

  回执末尾附一段"请据此修订，并按 schema 输出"的提示词（复用 `PlanSchemaJSON`）。出口只有两个：复制和系统分享，不联网。
- **A2 带记忆的一句话生成**：确认页加一个开关"带上最近 4 周记录"，由 `AIPromptBuilder` 注入回执摘要，设一个字数上限。
- **A3 版本对比校对页**：新计划和当前计划逐天、逐个动作对比，列出：
  - 新进、换下的动作
  - 组次和重量的变化
  - 来自历史的事实标注，比如"上次标过疼"
- **A4 改外来计划的"调整"入口**：首屏改成"带着记录回去问"，本地重排降为次要选项，并明说它会替换掉用户导入的计划。
- **边界**：App 依然不提建议，只负责整理证据；新计划仍然必须过校对页（ADR-0003、ADR-0004 不变）。

### B 记准：把重量记进账本

- **B1** `SetLog` 加可选的 `actualLoad`：
  - 训练页默认沿用处方重量，用户什么都不做就不增加操作。
  - 旧日志这个字段为空时，按处方重量处理，和 `planDate` 的回落是同一个做法。
- **B2 器械档位**：记录用户的哑铃是可调的（以及步进多少）还是固定的几个重量。这个问题第一次遇到负重动作时再问，不加进引导。加重提案改成"取下一个可用档位"，没有更重的档位就转去加次数或加组数。
- **B3 纪录口径**：按"动作 + 重量"分开比较，新增"首次用 X kg 完成"这类纪录。不引入 e1RM，并写明理由。
- **B4 剂量规则读实际重量**：
  - 用户自己加了重量、次数少了，不算没完成，也不触发"太累"。
  - 连续两次都自己加重，就给一条纠偏提案："把处方改成你实际用的重量"。

### C 弹性：让计划适应今天

- **C1 今天只有 N 分钟**：
  - 训练卡上提供 10、15、20 分钟三档。
  - 由一个 `SessionCompressor` 纯函数负责缩短：每个主导肌群保留第一个动作，削减组数，次数和重量不动。
  - 不改计划，也不改版本号。
  - 短版里的"没时间"不再进入减量规则。
- **C2 训练中换一个**：
  - 候选动作 = 低阶替代，加上"主肌群有交集、且器械可用"的动作（沿用 ADR-0005 的判据）。
  - 只对这一次训练生效，`SetLog` 记下换掉的是哪个动作。
  - 同一个动作被换掉两次，就交给现有的"换动作"提案。
- **C3 断点续练窗口**：从 30 分钟延长到当天有效。先加一个 `checkpointExpired` 计数，拿到证据再改。
- **C4 提醒跟着实际开练时间走**：同一个星期几，最近三次实际开练都比提醒晚 40 分钟以上、而且方向一致，就提案挪动提醒时间。走现有的提案、采纳和拒绝记忆，不改计划版本号。

每条主线都给出验收标准，并把需要的计数加进 `LocalCounter`，例如 `receiptCopied`、`shortSessionStarted`、`swapUsed`、`checkpointExpired`。

## 第 5 节：顺序与成本

1. **第一批**
   - B1 + B3：重量字段越晚加，缺重量的历史就越多，所以最先做。
   - A1 回执：成本最低，用来验证用户到底会不会把记录带回去。
   - 修 [DongKe/Features/Plan/PlanView.swift](DongKe/Features/Plan/PlanView.swift) 第 86 行：那里显示的是动作库的总数 `ExerciseLibrary.all.count`，不是这份计划里有几个动作。
2. **第二批**：C1 短版、C2 换一个。
3. **第三批**：A2、A3、A4，以及 B2、B4。前提是 A1 的数据证明用户真的会把记录带回去。
4. **第四批**：C3、C4，看计数再决定做不做。

## 第 6 节：不做什么

- 对外来计划主动提建议（ADR-0003）。
- 让计划自动生效。
- 用云同步来代替回执。
- e1RM 大图表。
- 社交功能。
- 跟练分路：BACKLOG §7 的结论维持不变。
- Live Activity 和 Watch：维持 BACKLOG §10 的判据，C 线做完后再重新评估休息倒计时的可见性。

## 第 7 节：需要拍板的决策（每条附推荐答案）

1. **短版的口径**。推荐：算"练过（短版）"并计入本周 x/y，完成率的分母用短版的组数。这一条和 `HistoryStats.isDone` 现在的口径（全部组完成才算练过）冲突，必须明确定下来。
2. **外来计划导入新版本时，版本号要不要加一**。推荐：用户在对比页勾选"这是上一份的新版本"时才加一，这样个人纪录和对照能连续下去。
3. **回执里包不包含伤病和疼痛信息**。推荐：包含，但复制前让用户先预览，并且可以删掉。
4. **器械档位在哪里问**。推荐：第一次遇到负重动作时再问，不加进引导。
