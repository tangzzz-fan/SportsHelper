# 动作图示素材替换 + Liquid Glass 界面落地

状态：ready-for-agent
日期：2026-10-22
依据：`docs/FROZEN-BASELINE.md`、`docs/SPEC.md`（本 spec 与其冲突处，以本 spec 为准，并触发 T01 的冻结文档补丁）

## Problem Statement

训练执行屏上的动作图示目前是自绘的 12 关节线稿骨架，一套 18 个动作的坐标数据全靠人手写，而且只有线、没有人体轮廓——用户做到一半停下来看，认不出「这是深蹲还是硬拉」。同时界面是扁平的：灰底、白色不透明卡片、大阴影，看不出这是 2026 年的 iOS 应用，用户明确要求「iOS 的玻璃质感」。

另外，动作图示的数据格式和渲染路径如果只为当前这一套素材写死，以后想换成另一个开源素材库（例如公有领域的那两个）就得重写渲染层，而这类替换早晚会发生——素材授权、画风、覆盖率都可能变。

## Solution

用开源素材库 `bryllim/workout-guide`（Everkinetic 重描，302 个动作，每个动作恰 3 帧 512×512 透明 SVG 单色线条插画，18 个 catalogId 全覆盖）替换自绘骨架：素材的 SVG 路径在**构建期**转成 SwiftUI `Path` 常量，运行期按路径真实包围盒等比适配，剪影填 `label` 色、底下垫一层 12% tint 光晕。图标默认静止，点按后三帧循环，再点停止；静力动作（平板支撑、靠墙静蹲、侧平板）只取第 1 帧。

界面按已验收的 `docs/design/2026-10-22-liquid-glass/index.html` 落地：玻璃是**真材质**（背景折射 + 内高光 + 外描边 + 镜面高光 + 顶亮底暗厚度边），不是白卡片加阴影。玻璃封装成一个表面修饰器，内部对 iOS 26 用原生 Liquid Glass、对 iOS 18 用 material 近似，页面代码里不出现版本判断。

素材来源必须**可替换**：图示数据通过一个来源协议暴露，当前实现读构建期生成的矢量路径；换源只需新增一个实现（例如读公有领域素材库的两帧位图），图示数据模型本身要能承载「矢量路径」和「位图帧」两种形态，页面代码不动。

## User Stories

1. 作为一个在家做训练的用户，我想在训练执行屏一眼看出当前是什么动作，以便不用回忆就知道该摆什么姿势。
2. 作为一个做到一半卡住的用户，我想点一下图示让它动起来，以便看清动作的起止轨迹。
3. 作为一个已经看明白的用户，我想再点一下让它停下来，以便余光里没有东西在动、不分散注意力。
4. 作为一个做平板支撑的用户，我想看到一张静止的、清晰的姿势图，以便判断自己的腰有没有塌。
5. 作为一个用深色模式的用户，我想剪影在深色背景上依然是亮的、可辨认的，以便夜里训练不刺眼。
6. 作为一个在 18 个动作之间切换的用户，我想每个动作的图示大小看起来一致，以便不会觉得某个动作「画得特别小」。
7. 作为一个打开 App 的用户，我想看到玻璃质感的导航条、卡片和浮动 tab 栏，以便这个 App 看起来是当前系统的原生应用而不是十年前的模板。
8. 作为一个近视但没戴眼镜的用户，我想休息倒计时在一臂距离外也能读清，以便不用凑近看还剩几秒。
9. 作为一个在两组之间喘气的用户，我想休息面板是半透明浮在训练画面上的，以便我知道自己还在同一个训练里、没有跳走到别的页面。
10. 作为一个夜间训练的用户，我想深色模式下玻璃有独立的配方（不是把浅色调暗），以便层次依然读得出来。
11. 作为一个用 iPhone 13（iOS 18）的用户，我想界面依然有玻璃的观感，以便我的设备不会因为系统版本被降级成塑料。
12. 作为一个用 iPhone 16（iOS 26）的用户，我想拿到系统原生的玻璃材质，以便和系统其他 App 的观感一致。
13. 作为一个动作被 AI 生成成白名单之外的用户，我想那个动作也有一个中立的图示，以便界面不会空一块让我以为坏了。
14. 作为一个维护者，我想图示数据只经过一条渲染路径，以便不用同时维护线稿骨架和剪影两套东西。
15. 作为一个维护者，我想换素材来源时只改一个实现，以便素材授权或画风变化不会波及页面代码。
16. 作为一个维护者，我想只要有一条路径缺帧、包围盒异常或动作缺失，构建期就报错，以便素材问题不会以「某个动作图是空的」的形式流到用户手里。
17. 作为一个维护者，我想 18 个动作的覆盖率、帧数规则、包围盒合法性都有自动化测试守着，以便替换素材时能立刻知道坏了什么。
18. 作为一个维护者，我想换源能力本身有测试证据（用假的位图来源跑通同一套接口），以便「以后能换」不是一句口头承诺。
19. 作为一个维护者，我想旧的自绘骨架管线和它的数据整体删除，以便仓库里不存在第二套图示口径。
20. 作为一个维护者，我想冻结文档（决策 6、骨架门禁、设计令牌）同步改写，以便后来者读到的只有一套口径。

## Implementation Decisions

### 图示模块（唯一的图示缝）

`DongKeCore` 内一个图示模块，对外只暴露四样东西：

- `ExerciseFigure`：值类型，含 `catalogId`、`frames: [FigureFrame]`、`motion: FigureMotion`（`.loop` 三帧循环 / `.hold` 单帧静止）、`bounds: FigureBounds`（三帧并集的包围盒）。
- `FigureFrame`：枚举，`.vector(VectorPath)` 承载 SVG 路径数据，`.raster(RasterFrame)` 承载位图引用（资源标识 + 像素尺寸）。**两种形态并存是换源能力的载体**，当前只生产 `.vector`。
- `FigureLibrary`：`figure(for catalogId: String) -> ExerciseFigure`。白名单内返回该动作；白名单外返回 `_generic` 占位图，**不返回可选值**——UI 不需要处理「没有图」这一状态。
- `autofit(bounds:into:padding:) -> CGAffineTransform`：纯几何，等比缩放 + 居中。

`FigureSource` 协议只做一件事：给定 `catalogId` 返回 `ExerciseFigure?`。当前实现 `BundledVectorFigures` 读构建期生成的路径常量。换源时新增实现并把 `FigureLibrary` 指向它即可，`ExerciseFigure` 与页面代码不变。

### 素材与生成

- 素材库：`bryllim/workout-guide`，媒体 CC BY-SA 4.0，每动作恰 3 帧，512×512 透明 SVG，单条实心路径（`fill-rule: evenodd`）。
- 构建期生成器：把每个动作的三帧 SVG 解析成 SwiftUI `Path` 构造代码，产出 Swift 常量（约 1MB 量级）。生成器同时输出一份 JSON 镜像（动作 → 帧数 → 包围盒），供测试校验，**测试不解析 Swift 源码**。
- 生成器负责算包围盒：单帧包围盒按路径几何采样（含曲线与圆弧），动作包围盒取三帧并集。并集让帧间不跳尺寸。
- 生成器失败即构建失败：帧数不对、路径为空、包围盒非有限值、18 个动作缺任何一个，都报错退出。

### 渲染口径

- 剪影填充 `label`（浅色近黑 / 深色近白），**不用 tint 填充**——tint 保留给选中态、进度和主按钮（每屏 accent ≤2 处的既有规则）。
- 剪影背后一层 12% tint 径向光晕（浅色 `rgba(14,124,102,.16)`，深色 `rgba(52,179,154,.18)`）。它同时是玻璃折射所需的内容层。
- 训练执行屏的背景保留一块放大到屏宽的剪影 ghost（12% 不透明度，tint 色），同样服务于折射。
- 静力动作：`motion = .hold`，只取第 1 帧，不循环。判定静力动作的清单是显式白名单（平板支撑、靠墙静蹲、侧平板），不靠动作名猜测。
- 交互：默认静止；点按开始三帧循环；再点停止回首帧。同屏只允许一个图示处于播放态。

### 玻璃材质

- 单个玻璃表面修饰器，参数为圆角与可选 tint 强调；内部两条路径：iOS 26+ 用系统原生玻璃，iOS 18 用 `ultraThinMaterial` + 手写内高光（1pt 白 55%）+ 外描边（0.5pt 白 25%）+ 顶亮底暗各 1.5pt 厚度边 + 120° 镜面高光。
- 深浅两套配方是独立令牌，不是同色反相：浅色白填充 14%，深色白填充 6%、描边 12%、高光 28%、模糊 26pt、tint 提亮为 `#34B39A`。
- 按压态：模糊从 24pt 降到 12pt、亮度 96%、缩放 0.98。
- 页面代码只写「这是个玻璃表面」，不写任何版本判断。

### 范围与依赖

- 部署版本维持 **iOS 18.0**（不因玻璃抬高）。
- 动作库仍锁 18 个 catalogId，不扩。
- 三个屏按已验收设计稿落地：今日（浅/深）、训练执行、休息计时。今日屏的数据来自内置示例计划（`docs/exercise-copy.sample.json` 同构），本轮不接持久化。
- 训练执行与休息的流程逻辑复用既有执行流模型与休息状态机，不重写。

### 换源准备（本轮只做契约，不做第二个实现）

- `FigureFrame.raster` 分支本轮不生产数据，但必须有测试证明它可以承载两帧位图并被正确渲染。
- 换源清单写进文档：公有领域素材库 `yuhonas/free-exercise-db`（The Unlicense，873 动作，每动作 2 张静图，中位 53KB，**缺开合跳 / 靠墙静蹲 / 鸟狗 / 高抬腿**，缺的走 `_generic`）；GIF 素材库 `hasaneyldrm/exercises-dataset`（媒体 © Gym visual，需署名，180×180 偏小）。

## Testing Decisions

好测试的标准：只测对外可观察的行为——给定 `catalogId` 拿到什么帧、几个帧、包围盒多大、变换是否正确；不测生成器内部函数、不测 Swift 视图结构。

**缝一：图示模块（`DongKeCore`，纯逻辑，现有测试同款）**

- 18 个 catalogId 逐个返回非空帧集，且 `catalogId` 回显正确。
- 白名单外动作（含 `custom_` 前缀）返回 `_generic`，且 `_generic` 至少 1 帧。
- 动态动作 3 帧、静力动作 1 帧；`motion` 与帧数一致（帧数与 `motion` 不自相矛盾）。
- 每个动作的包围盒宽高为正、有限、不超出素材画布。
- `autofit` 在「宽受限」和「高受限」两种情形下：等比（缩放因子单一）、居中（中心对齐）、不超界（含 padding）。
- 换源契约：用一个返回两帧 `.raster` 的假来源跑通 `FigureLibrary`，断言调用方拿到的仍是 `ExerciseFigure`、帧数为 2、`motion` 为 `.hold`，证明换源不需要改调用方。

**缝二：生成产物门禁（纯逻辑）**

- 读生成器输出的 JSON 镜像：条目数 = 19（18 + `_generic`）、每动作帧数符合规则、每条路径数据非空、包围盒合法。
- 该门禁取代原「骨架门禁」（原规则：specs 严格等于 18 + `_generic`、帧数 3/2/1）。新规则：18 个动作各 3 帧、`_generic` 1 帧、**不存在 2 帧条目**——素材里静力动作也是 3 帧，静力取帧是渲染期决定，不是数据期事实。

**人工验证（不进单测）**

- 三屏截图与设计稿比对（浅色 / 深色 / 训练执行 / 休息），存 `docs/design/2026-10-22-liquid-glass/shots/`。
- iOS 26 模拟器与 iOS 18 模拟器各截一次，确认两条玻璃路径都成立。

## Out of Scope

- 持久化（SwiftData）与通知排程：本轮界面用内置示例计划驱动，不落库、不发通知。
- AI 直连计划生成、Keychain、错误映射。
- 动作库从 18 扩到其他数量。
- 上架合规：CC BY-SA 4.0 的署名页 / share-alike 处置（用户明确本轮不上架）。
- 第二个素材来源的真实实现（只做契约与文档，不做 `free-exercise-db` 的下载与打包）。
- 久坐提醒（P1）。

## Further Notes

- 素材是**单色线条插画**：整张图是单条 `fill-rule: evenodd` 路径，墨线本身由一圈细轮廓填充而成——所以「填 label 色」渲染出来是线条画，不是实心块。配色因此用 label 而不是 tint，光晕负责托底。
- 素材每帧自带 `attribution`（作者、来源、许可、改动说明）。本轮不做署名界面，但生成器应把 attribution 一并写进 JSON 镜像，将来要出署名页时数据在。
- 换源成本估算：新增一个 `FigureSource` 实现 + 一张「catalogId → 素材 id」映射表；页面、状态机、测试缝一全部不动。缺图动作统一回退 `_generic`。
- 旧的自绘骨架体系（12 关节位姿 + 插值）没有测试覆盖，删除不会掉绿；但它是 FROZEN 决策 6 的产物，删除必须同步改写冻结文档（T01）。
