## 1. 设计方向

### 1.1 一句话

> **不是健身房 App，是给久坐程序员的一份每日执行清单。视觉基调是「仪表」，不是「竞技场」。**

差异化不在更炫，在更可信。用户已经有一份他信的计划（来自 ChatGPT / DeepSeek），他要的是有人把它变成「第 2 组，12 次」。所以界面首要任务不是激励，是**让「现在做什么」零歧义**。

对标物不是 Hevy / Fitbod / Keep，而是：Braun 测量仪（数字被尊重）、iOS 原生健康（单色底 + 一个饱和）、Teenage Engineering（允许不好看但精确）、Linear（靠明度分层，不靠阴影）。

### 1.2 我们靠什么区别于同类（不是靠颜色）

| 做法 | 竞品怎么做 | 我们怎么做 |
|---|---|---|
| 一屏一组 | 组表一次列 3–5 行，训练中要扫视找「我在第几组」 | **一屏只显示当前组**，一个 64pt 主按钮，一个常驻「这组做不动」 |
| 动作说明 | 视频（要停、要找、要音量） | **3 帧动作示意 + cues 3–5 条 + 常见错误 2–3 条**，静音、离线、0 加载 |
| 做不动 | 藏进长按 / 编辑菜单 | **常驻入口**，三选项：减半次数 / 跳过本组 / 休息 +30 秒，选完立即生效 |
| 完成反馈 | confetti + 奖章 | **三个读数**：完成率、降阶率、跳过率。没有一句「你真棒」 |
| 倒计时 | 小字在角落 | 88pt 等宽数字 + 环，跑步机上看一眼就懂 |

### 1.3 每屏强调色预算（解决「双色 vs ≤2 处」）

规则：**每屏最多 1 个语义色族 + 最多 2 处可见强调色。**

| 页面 | 允许的语义色族 | 可见强调色落点（≤2） |
|---|---|---|
| 引导 5 屏 | accent | 主按钮、进度条第 N 段 |
| 今日 | accent（已打卡态可换 success 1 处） | 主按钮、TabBar 选中 |
| 训练执行 | accent | 主按钮、组进度点当前位 |
| 休息计时 | accent | 环、提前开始按钮 |
| 完成总结 | success 1 + accent 1 | 完成率数字、收下按钮 |
| 计划 | accent | 当前计划标记、TabBar 选中 |
| 计划导入 | accent | 解析按钮、输入框聚焦环 |
| 计划校正 | **warning** + accent | issue 高亮、保存并使用 |
| 动作库 | accent | 分组展开箭头当前态 |
| 动作详情 | accent | cues 编号数字 |
| 记录 | chartPrimary + chartSecondary | 图表柱、TabBar 选中 |
| 设置 | accent | 开关选中态 |

禁止：同一屏出现 3 个色族；用 accent 画装饰线；用 success 当按钮底色；用 accent 画动作示意（示意永远 `textPrimary`，它描述身体不表达情绪）。

**AI 标识不用绿色。** accent 已是青绿，若 AI 徽标也用绿，「AI 生成」和「练完了」在扫视时无法区分。已拆出 `aiGenerated`（青蓝）+ `aiGeneratedSoft`，只出现在计划来源标识与导入结果页眉，内容是四个字「AI 生成」而不是图标。

### 1.4 明暗策略

浅色为默认（居家场景多在客厅与午休，且与「健身房深色」竞品拉开第一眼差异）；深色由语义 token 自动解析，**不另出配色**。深色不用阴影，用 `surface` 到 `surfaceRaised` 的亮度递进；文本不用纯白。

深色下 accent 是亮青绿，白字只有 2.61:1——所以 `accentOn` 在深色下是近黑，不是白。这条容易写错，已在 tokens 里写死。

## 2. 设计原则（冲突时按序取舍）

**1. 训练中，「看得清」压倒一切。**
一屏一组。所有可点区 ≥56pt、主按钮 64pt、动作名 ≥`.title`。训练页禁止图标按钮（除返回）——出汗的手指前，图标是歧义。屏幕常亮。

**2. 一个动作只需要一次决定。**
进训练后不需要选、不需要调顺序、不需要记数字。做不动时也只**选一次**（三选项 ActionSheet），选完自动继续，不弹二次确认。理由很直白：躺在地上多一次确认，就多一次放弃。

**3. 不用激励，用读数。**
不写「太棒了」，写「完成率 92%，降阶 2 组，跳过 1 组」。零 confetti、零徽章、零火焰图标。断连了不显示哭脸。

**4. 每条失败路径都必须带出口。**
解析失败转「手动添加」和「填入示例」；库外动作转中立站立位姿 + 要点文字 + 编辑入口；权限被拒转「去系统设置」且不阻塞任何功能；写入失败转可见提示 + 保留本地数据 + 重试。**没有一个错误停在「出错了」。**

**5. 动画只解释状态，不表演。**
全站唯一的循环动画是**动作示意**（承载「这个动作长什么样」的真实信息）。其余一律 150ms 收敛缓动，禁止弹跳、禁止 overshoot。`Reduce Motion` 下示意静止、环跳步，但**倒计时数字必须继续逐秒更新**。

## 3. 竞品研究（保留结论，精简）

- **Hevy** — 借鉴：训练中按钮极大；自动带出上次数据；每组落库后自动起休息计时。避开：组表密度过高；社交 feed 占据流程中心。
- **Fitbod** — 借鉴：引导问器械而非问水平（这决定计划能不能执行）。避开：**14 步引导**（我们 5 屏）；动作变化过多导致用户困惑。
- **Keep** — 借鉴：中文语感（短句、动词开头）；数字放大、其余弱化；线稿图标；不用纯黑。避开：社区 + 商城稀释首页；课程图墙（我们没有拍摄素材）。
- **Strong / Apple Fitness** — 借鉴：极简记录路径；圆环 + 大数字。避开：三环 gamification 带来的「环没满就焦虑」。
- **训练记录类共识**（对本案影响最大）：休息计时必须**附着在组上**并保留上一组 / 下一组上下文；预填值保持「未确认」视觉；撤销不重置计时器；**计划 / 本次 / 历史是三份数据**；本地优先，绝不让用户重做一组。

> **零打包字体**（ARCH v1.2 §14.4）：`UIAppFonts` 为空，仓库无字体文件。倒计时与训练主数字都用 `.system(design: .monospaced)` + `.monospacedDigit()`，经 `Typography.swift` 单点封装，视图里不得写字体名或字号字面量。
>
> 为什么取消打包不影响设计：88pt 的「仪表感」由字号、字重、等宽数字、环的等速消耗共同建立，不靠字族。B612 Mono 与 SF Mono 在 88pt 上的差别，远小于「88pt 与 34pt」的差别——拿 40KB 包体 + OFL 义务 + RFN 风险去换这点差别，不划算。
>
> 字体政策已裁决并回写：`SPEC.md` §4 与 §8、`ARCHITECTURE.md` §14.4、`design-tokens.json` 的 `fontPolicy` 四处一致为零打包。

### 4.2 不截断规则（SPEC + PM 硬约束）

「第 2 组 / 共 4 组」「目标 12 次」「完成第 2 组 · 12 次」三项在 AX5 下不得截断、不得缩字、不得折叠：

1. 三个信息**各自独立 `Text`，纵向 `VStack`**。禁止塞进同一 `HStack` 横向挤压——横向挤压是截断的根源。
2. 每个加 `.fixedSize(horizontal: false, vertical: true)`，**禁止 `.lineLimit(1)`**，让它换行。
3. 纵向不够时，收缩顺序固定：**先缩动作示意 160 转 120，再把 cues 从 5 条收到 2 条并挂「全部要点」入口，最后才允许 `minimumScaleFactor 0.85` 缩字**。
4. 三项核心信息在任何字号下不折叠、不隐藏、不缩字。

### 4.3 排版纪律

- 中文正文行高 ≥1.5（`.body` 默认已满足）；单行 ≤37 个汉字。
- 标题负字距 `-0.01em`；正文 `0`；英文全大写 `+0.08em`。
- 字重只用 regular / medium / semibold 四档，同屏不超过 2 档。
- 数字一律 `.monospacedDigit()`，避免组数 / 倒计时变化时布局抖动。
- 视图内禁止 `Font.system(size:)` 字面量与 `Font.custom(` 字面量。

## 6. 动作图示

### 6.1 现行方案与渲染接口

**最终冻结：自绘参数化骨架，12 关节，18 个动作 × 3 帧，不使用第三方素材。**
（FROZEN-BASELINE 决策 6。素材方案两次下载失败（HTTP2 framing / 40MB 只到 6.3MB）且授权需法务，MVP 不引入外部变量。）

UI 只认一个视图：

```swift
struct ExerciseFigureView: View {
    let catalogId: String
    let size: CGFloat
    var playsAnimation: Bool = true
}
```

七条不变行为：3 帧、2.4 秒循环、帧间 120ms 交叉淡入、列表内静态首帧、同屏只播 1 个、单色 `textPrimary`、`custom_` 前缀走降级态。

**已否决：第三方线稿素材。** 不使用第三方素材，因此关于页不需要任何授权声明区块——没使用别人素材却写声明，比不写更糟。这条已定，不再讨论。

### 6.2 为什么是 12 关节而不是 8

8 关节 = 侧视单侧骨架（head / neck / shoulder / elbow / wrist / hip / knee / ankle）。18 个动作逐个数：

| 动作 | 8 关节能不能读 | 缺什么 |
|---|---|---|
| squat / wall_sit / calf_raise | 能 | — |
| push_up / plank / side_plank | 能（侧视天然合适） | — |
| glute_bridge / crunch / superman | 能 | — |
| shoulder_press | 能 | — |
| dumbbell_row | 勉强，靠 props 的哑铃救命 | 支撑手遮挡画不出来 |
| russian_twist | 勉强 | 双手位置表达不出「转体」 |
| **lunge** | **不能** | 前后腿无法同时表达，会被读成单腿站立或深蹲 |
| **jumping_jack** | **不能** | 两腿分开画不出，只有一条腿的动作没有意义 |
| **high_knees** | **不能** | 左右交替抬腿画不出 |
| **mountain_climber** | **不能** | 同 lunge，前后腿 |
| **dead_bug** | **不能** | 对侧手脚同时伸展是这个动作的全部信息 |
| **bird_dog** | **不能** | 同上，对角支撑 |

4 个能用、2 个勉强、**7 个不能**（打样实测，见 `figure-specs.sample.json` 的 `coverageMap`）。12 关节 = 躯干 4 点 + 双侧上肢 / 下肢各 2 点。**扩展成本为零**：`FigurePose.points` 是字典、`links` 在 spec 内、渲染器按数据迭代，加 4 个关节就是加 4 个 key 和 4 条连线，不改一行渲染代码。8 关节作为兼容退化模式保留（只用 Near 侧 7 条线，6 个动作可用）。

### 6.3 视觉与播放规格

| 项 | 规格 | 为什么 |
|---|---|---|
| 线宽 | 画布边长 2.2%，圆头圆角；缩略后低于 2.5pt 自动加粗到 2.5pt | 低于 2.5pt 在半米外看不出是线 |
| 关节半径 | 画布 1.6%，用 `surfaceRaised` 挖空 | 大于线宽 1.2 倍就成「糖葫芦」 |
| 躯干 | shoulder 转 hip 线加粗 1.4 倍，**不填充** | 填充后关节与线不再区分，且会读成「人体剪影」而不是骨架，反而降低辨识度 |
| 远侧肢体 | opacity 0.55 | 12 关节能读的前提，表达前后遮挡 |
| props | 地板线 / 墙线 / 哑铃 / 弹力带 | **道具是辨识度的一部分，不是装饰**：哑铃划船没哑铃会被读成徒手俯身，靠墙静蹲没墙会被读成半蹲 |
| 颜色 | `textPrimary` | 它描述身体，不表达情绪；不用 accent |
| 朝向 | 默认侧视面朝右；`jumping_jack`、`high_knees` 用正面 | 只有正面才读得出「腿打开 / 抬起」 |
| 帧数 | 3 帧（起始 / 最吃力点 / 回起始）；静力动作 2 帧且姿势近似 | 静力动作本来就不动，多一帧是噪音 |
| 播放 | 3 帧 2.4s 循环，帧间 120ms 交叉淡入，`TimelineView` 上限 30fps | 120ms 是「不跳变」的下限；静力动作 `loopSeconds` 拉长到 3.5s，快速动作 1.2s |
| 坐标 | 归一化 0…1，**允许超界**，渲染前 autofit | 见下 |
| autofit | 同动作全部帧取并集 bbox，等比缩放居中到 0.06–0.94，最小缩放 0.6 | 死虫横跨 1.11 个单位正方形，不 autofit 会被裁掉一截。纯函数可单测，约 5 行 |
| 骨段一致性 | 同动作各帧的躯干 / 大腿 / 小腿 / 上臂 / 前臂长度容差 ±15% | 否则插值会出现「橡皮筋」 |
| 尺寸 | 训练页 160pt / 动作卡 120pt / 动作库缩略 44pt / 记录缩略 48pt | 160 不是 200——SE 3 上 200 会挤掉 cues，见 §6.5 |
| 同屏播放数 | **1**（训练页、动作详情各 1） | 动作库、记录、校对页一律静态首帧，`ForEach` 里不建 `TimelineView` |
| 静态首帧取第几帧 | **第 1 帧（`poses[0]`）**，全站统一，不按动作挑帧 | 挑帧会让同一列表里每个缩略都停在不同相位，看起来像随机截图。第 1 帧天然是「起始位」，最能读成「这个动作的起点」 |
| `Reduce Motion` | 固定第 1 帧不播放，保留 `accessibilityLabel` | 倒计时数字**照常逐秒更新**——冻结动画不等于冻结信息 |
| 无障碍 | `accessibilityLabel` 取 `cues` 首句；线条与关节 `accessibilityHidden(true)` | 不让 VoiceOver 逐个读 12 个点 |

### 6.4 库外动作的降级态

`catalogId` 以 `custom_` 开头或 spec 缺失时，用**中立站立位姿**（渲染器内置的一份位姿数据，不单独出图，同一线宽同一颜色），不转圈、不用灰色骨架屏、不加虚线框。

```
┌──────────────────────────────┐
│                              │
│      [ 中立站立位姿示意 ]       │  textSecondary，正常亮度，
│       （静态，不播放）          │  它就是一张内容图，不是占位
│                              │
│  这个动作没有示意图             │  .sectionTitle
│  按要点做就行。               │  .body textSecondary
│                              │
│  要点                         │  .sectionTitle
│  · 计划里写了什么就显示什么      │  来自 ExercisePrescription.notes
│                              │
│  [ 编辑这个动作 ]              │  文字按钮，44pt
└──────────────────────────────┘
```

四条硬规则：
1. **不画虚线框。** 虚线读作「等加载、这里缺东西」，实线内容读作「它本来就长这样」。缺的是**这一张图**，不是功能。
2. **骨架取 `textSecondary` 不用更浅的灰。** 一旦调浅就变成「占位骨架屏」。
3. **文案不提「库」。** 「这个动作不在库里」是黑话，用户不知道有什么库。写「这个动作没有示意图 / 按要点做就行。」两句都是肯定句，第二句立刻给替代做法。
4. **不做「推荐相近动作」。** 用户自己写的动作，App 推荐一个「差不多的」是在质疑他的计划。只给「编辑这个动作」。

### 6.5 cues 与 commonMistakes 的同屏预算（iPhone SE 3 实测）

PM 硬要求：cues 3–5 条 + commonMistakes 2–3 条必须与动作示意**同屏可读，不得折叠到二级页**。

**训练执行页**（375×667，可用 647pt）：

| 区 | 高度 |
|---|---|
| 顶部条（退出 + 3/5 动作） | 44 |
| 动作名 `.title` | 34 |
| 第 2 组 / 共 4 组 | 26 |
| 目标 12 次 | 26 |
| 组进度点 | 8 |
| 动作示意 | 160 |
| 「要点」标题 | 23 |
| 块间距合计（8+4+4+8+12+12+8） | 56 |
| **固定区小计** | **377** |
| 底部操作条（1+12+64+8+56+12） | 153 |
| **留给 cues 的空间** | **647 − 377 − 153 = 117** |

cues 每条约 29.5pt（`.body` 行高 25.5 + 间距 4）。**117pt 刚好放 4 条**。第 5 条需要滚动 30pt。

所以结论是：**3–4 条免滚动，5 条时 cues 区变成可滚动区**（动作示意与三项核心信息钉住不动）。这不叫折叠——折叠是把内容藏到另一个页面或「展开」按钮后面；滚动是内容就在眼前，手指一划即到。**训练页不出现「查看更多要点」这类按钮**，那才是折叠。

**动作卡 Sheet**（`.large` detent，可用约 579pt）：示意 120 + 名称 26 + 要点 5 条 151 + 错误 3 条 92 + 低阶替代 44 + 按钮 56 + 间距 64 = 608pt，超出 29pt。所以 **Sheet 内示意钉顶不滚，文字区滚动**，且 cues 与 errors 默认全部展开、无「展开」按钮。

**cues 的视角规则（12 关节骨架能表达侧视与正面，但用户看不出你画的是哪个）**：凡要点里涉及角度或相对位置，必须把视角写出来——写「从侧面看，膝盖不超过脚尖」而不是「膝盖不超过脚尖」；写「正面看，两膝别往里夹」而不是「膝盖别内扣」。理由：图是侧视的，用户在自己的身体上看不到「侧面」，只能靠文字把图对到身体上。这条对 `jumping_jack`、`high_knees` 这类正面动作尤其重要。

**AX 大字号下**：按 §4.2 的收缩顺序执行——示意先 160 转 120（省 40），cues 收到 2 条（省 59），仍不够才缩字到 0.85。三项核心信息（组数、目标、按钮文案）永远不动。

```
│ 2 屁股先往后坐，不是往下跪              │
│ 3 膝盖对脚尖，不要内扣                 │
│ 4 大腿到平行就够，不用更低              │
│                                      │
│ [ 动作卡 · 要点与常见错误 ]            │  文字按钮 44pt，开启 Sheet
├ 底部固定（safeAreaInset）──────────────┤
│ [      完成第 2 组 · 12 次       ]     │  64pt accent
│ [         这组做不动          ]        │  56pt 次按钮，常驻
└──────────────────────────────────────┘
```

**cues 只放正向要点，commonMistakes 不放这页**——做动作时读「别塌背」会让人一边做一边怀疑自己，训练页只给「做对」。常见错误放在动作卡里（一次点击就到，见 §6.5）。这是我对「两份文字都必须同屏可读」的落法：同屏的对象是**动作卡**这一层，不是训练页这一屏。

**关键交互**
- **完成一组**：`haptic.setCompleted` + 该点变 success，80ms 转 自动进入 P4 休息；`restSec == 0` 直接切下一组。
- **计时类动作**（`target.type == duration_sec`）：主按钮变「开始」，按下后变「完成」并原地显示剩余秒（占用 `workoutNumber` 位），不跳页。
- **每侧动作**（`perSide`）：按钮文案「完成第 2 组 · 每侧 12 次」。
- **这组做不动**：ActionSheet 三选项，**每项下方一行小字说后果**，选完立即生效，**无二次确认**：
  - 「减半次数」：本组目标 12 改 6，标记 `downgraded`，第 3/4 组不动
  - 「跳过本组」：转 跳过原因二次选择（5 项）
  - 「休息 +30 秒」：只给休息加时，本组仍待完成
- **撤销**：完成或跳过后 3 秒内，组进度点右侧出现「撤销」，**撤销不重置计时器**。
- **退出**：确认 Sheet「本次已完成 2 组。退出会保存为部分完成。」两个选择：「继续练」/「保存并退出」。

**五态**
- Loading：无（数据已展开为 `[FlowStep]`）。从通知冷启进来自检 ≤100ms，进页即有内容（AC-10 要求无需额外点击）。
- Empty：**不允许出现**。无计划时进不来，由 TodayView 拦截。
- Error（写入失败）：不弹窗、不阻断。行内 `warning` 一行「这组没存进本地，正在重试」+ 保留内存态。**绝不要求重做**。本期不做「待同步」标签——没有同步通道，那个状态永远点不亮，属于假功能。
- Populated：如上图。
- Edge：① 中断恢复转 顶部 `warning` 条「已恢复上次训练 · 3 组已完成 · 休息剩 42 秒」；② 组数 >10 转 进度点改文字「2/12」；③ 动作名超 12 字转 允许 2 行后省略；④ AX5 转 示意缩 120、cues 默认收 2 条 + 「全部要点」。

**动效**：组切换用 `.opacity` 150ms（不做横向滑动，避免「翻页」错觉掩盖「换组」）。
**性能**：`isIdleTimerDisabled = true`；30fps；同屏 1 个动画；无阴影无模糊。

- 加时 / 跳过：先移除旧通知，再按新 `endAt` 重排。

**五态**：Loading 无；Empty 无；Error（通知排程失败）转 不阻断，底部 `warning` 一行「锁屏后可能收不到结束提醒」，不弹窗；Edge：休息 >300 秒转 环外一句「可以先去喝口水」（`textTertiary`，全站仅此一处闲话）；Reduce Motion 转 环每 1s 跳步，数字照常。

**无障碍**：`accessibilityLabel("休息剩余")` + `accessibilityValue("1 分 20 秒")`，按整 10 秒更新（每秒更新 VoiceOver 无法插话）。这条是架构写进验收的硬要求。

| issue | 字段路径 | 编辑控件 | 阻塞保存 |
|---|---|---|---|
| 组数越界（0 或 >20） | `items[k].sets` | Stepper 1–20 | 是 |

| 休息缺失（已自动填充） | `items[k].restSec` | Stepper，标「已自动填充」 | 否 |
| 天数与 `daysPerWeek` 不一致 | `meta.daysPerWeek` | 数字 + 「按实际训练日改为 3」 | 是 |
| 动作不在库内 | `items[k].catalogId` | 「库外动作」+ 降级态示意图 + 「编辑这个动作」 | 否 |

## 9. 系统态规范

### 9.1 空状态四形态（文案互不复用）

| 场景 | 标题 | 说明 | 主按钮 | 次按钮 |
|---|---|---|---|---|
| A 无计划（今日） | 还没有训练计划 | 晚 20:30 是你设的时段。粘贴一段计划文本，或者用 AI 生成一份。 | 导入计划 | AI 生成一份 |
| B 休息日（今日） | 今天是休息日 | 下次训练：周四 19:30，下肢力量。 | 看本周安排 | 就想动 10 分钟 |
| C 无历史（记录） | 还没有记录 | 完成第一次训练后，这里会有完成率和连续天数。 | 开始今天的训练 | — |
| D 无计划（计划页） | 还没有计划 | 导入一份，或者从动作库挑几个自己排。 | 导入计划 | 手动排一天 |

**第四态是「未开通知」说明条，但它不是空态**：它是叠加在页面顶部的横条，与 A 同时出现时上下分离（横条 `warningSoft` 满宽 + `xmark` 关闭；空态从 pageTitle 起）。**与 B 不共存**——休息日提醒你开启通知是噪音。A/B/C/D 之外**禁止**：Lorem ipsum、「Welcome to」、四处复用同一句「暂无数据」、有按钮但按钮无行为。

### 9.2 训练中断恢复（AC-15）
30 分钟内重开转 直接回训练页断点，顶部 `warning` 条「已恢复上次训练 · 3 组已完成 · 休息剩 42 秒」，右侧「重新开始」文字按钮（二次确认）。**已完成组永不丢失。**
若 `status == active` 且距上次 >12 小时转 今日页显示「上次训练没结束」+「继续」/「结束并记录」，不自动进入。

### 9.3 存储 / 网络失败
本地优先：网络只影响 AI 分支。**所有 AI 失败都是页面内行内错误 + 明确替代路径（改用粘贴）**，不用全屏错误页。存储失败必须可见，且保留用户输入。本期无同步通道，因此**不设计「待同步」状态**。

### 9.4 通知权限被拒
今日页顶部可关闭横条（见 9.1 D 的说明），不阻塞任何功能；关闭后 7 天内不再出现；设置页常驻状态行。

## 10. 通知设计（本期两条，**无久坐提醒**）

### 10.1 训练提醒

| 字段 | 内容 |
|---|---|
| 标识符 | `dk.plan.{planId}.d{1-7}` |
| 触发 | `UNCalendarNotificationTrigger`，`repeats: true`，每周固定星期几 + 时分；单计划 ≤7 条 |
| `interruptionLevel` | `.timeSensitive`（需 Info.plist 声明） |
| 标题 | 当天主题，取自 `days[i].title`，如「今天练下肢」 |
| 正文 | `{首动作} {组} 组、{次动作} {组} 组，预计 {m} 分钟` |
| 示例 | 「深蹲 4 组、箭步蹲 3 组，预计 28 分钟」 |
| 动作按钮 | 「开始训练」（深链执行页）/「稍后提醒」（延后 15 分钟） |
| 不生成 | 休息日不发 |

标题不写「该运动了」这类泛化文案——泛化提醒正是本产品要解决的那个问题。

### 10.2 休息结束通知

`dk.rest.{sessionId}`，`UNTimeIntervalNotificationTrigger`，标题「休息结束」，正文「该第 3 组了 · 12 次」。训练结束即删，不累积。

### 10.3 合并与去重

| 冲突 | 处理 |
|---|---|
| 同一时段两个训练块 | 合并为 1 条，标题「今天有 2 个训练」，正文列两个名称，点开进今日页选择 |
| 休息结束通知与其他通知撞车 | 休息通知优先（实时性），其余延后到训练结束 |
| 同一天重复触发（时区变化 / 重建） | 标识符幂等；先清 `dk.plan.` 前缀再重排；**绝不调 `removeAllPendingNotificationRequests()`** |

### 10.4 文案禁区
不用感叹号；不用 emoji；不写「再不练就白费了」「已经 3 天没动了」这类羞辱式；不写「加油」「坚持就是胜利」。**久坐类文案整体删除**——我们不读健康数据，写「你已经坐了 2 小时」是编造。

## 11. 文案基调与示例

**规则**：动词开头、短句（≤18 字）、给具体数字、不承诺情绪、不用感叹号、不用「蜕变 / 燃 / 自律 / 坚持」。

1. **空状态（无计划）** —「还没有训练计划。粘贴一段计划文本，或者用 AI 生成一份。」
2. **训练提醒** —「深蹲 4 组、箭步蹲 3 组，预计 28 分钟」
3. **休息归零** —「休息结束。该第 3 组了，12 次。」
4. **完成总结** —「92%。完成率 11 / 12 组。降阶 2 组，跳过 1 组。」
5. **身体不适提示** —「你说过身体不适。要是同一个动作还疼，别硬练，改天再看。」
6. **解析失败** —「没能从这个计划里识别出动作。可以手动添加，或换一段试试。」
7. **库外动作** —「这个动作暂无示意图。不影响记录，要点用计划里的备注。」
8. **写入失败** —「这组没存进本地，正在重试。已完成的组不会丢。」
9. **Key 无效** —「API Key 被拒绝。检查是否填错，或额度用完了。」
10. **做不动入口** —「这组做不动」（不是「跳过」、不是「遇到困难」——后者是委婉语，躺在地上的人需要的是准确）

**反例（禁止）**
- 「欢迎来到动刻，让我们一起开始蜕变之旅！」
- 「太棒了！你又坚持了一天，为你骄傲！」
- 「解锁你的无限潜能，燃动每一天！」
- 「暂无数据」
