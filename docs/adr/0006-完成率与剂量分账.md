# 完成率与剂量分账

**Status:** accepted（2026-10-25）

会话里允许「今天再加一组」之后，同一个训练日会同时存在两种组：计划内的，和用户当场加的。这两类组必须分开记账，否则两个数字都会说谎。

**完成率回答「计划做完没有」，剂量回答「练了多少」。** 完成率的分母锁在进入训练时展开的计划组数（`WorkoutFlowModel.plannedSets`），会话中加组不改它；额外组进分子以外的单独计数。这样跳过第 12 组、又加做第 13 组，仍然是 11/12，不会互相抵消。`HistoryStats` 的「这一节练过没有」同样只认计划内完成——否则用户可以在没做计划的情况下把一节课"补"成练过。

额外组**算剂量**：它是真实做掉、带自评强度的一组，进本周有效组与肌群分布，但带 `SetOrigin.extra` 标记。这样记录页能同时回答「计划内多少 / 计划外多少」，而不用把两个问题压成一个数字。

静态动作（`durationSec`）的进阶轴单独定：余力连续两次 ≤ 2，保持时间 +5 秒，上限 60 秒；到顶后沉默，不转成加组。减量也走同一根轴——疼痛或太累时减保持时间，不减组数。`distanceM` 没有进阶轴。

**Considered options**：① 加组进分母。直观，但「跳过一组 + 加做一组 = 100%」会让完成率失去检验计划执行度的能力，也会让 `isCompleted` 误判。② 两个完成率都显示（锁分母 + 含加组）。信息完整，但一屏出现两个百分比，用户要先理解差别；额外组数已经能表达同一件事。③ 额外组不算剂量。剂量严格对应计划，但用户真练了却不记账，违背「有效组＝接近力竭的真实刺激」。④ 静态动作按百分比进阶。5 秒的 10% 取整后常常没变化，30 秒变 33 秒也不好播报。

**Consequences**：新增 `SessionLedger` 作为会话计数的唯一出处（完成 / 降阶 / 跳过 / 额外，以及有效组判定），`SessionRecap`、`WorkoutSession`、持久化都从它取数，UI 不再自己数 logs。`SetLog` 增加 `origin`，旧 checkpoint 缺字段或遇到未知值时都按计划内解码；`SetLogEntity` 加可选 `originRaw`，旧库无值回落计划内。`SessionEntity.completedSets` 仍存计划内完成数，`HistoryStats` 语义不变。播报暂只报计划口径，额外组另开票补。记录页新增 `extraSets`，与 `effectiveSets` 分开显示。

不做：按肌群拆分母、把额外组写回计划、把「加一组」当成立即修改处方（ADR-0004 仍适用——当场加的是训练量，不是计划）。
