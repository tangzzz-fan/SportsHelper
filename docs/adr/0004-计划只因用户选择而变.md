# 计划只因用户选择而变

**Status:** accepted（2026-10-25）

剂量回路接上之后，App 第一次能在用户不知情时改变处方。立一条总原则：**计划只因用户选择而变**。三个入口——用户主动改、系统据「多次放弃或延迟」提出建议、以及后续新增的其它入口——都必须经过同一个动作：把变更摆出来，用户点了才落库。**没有自动生效的路径，一条都没有。**

同时定一条语气原则：用户既已选择，就默认他是**乐观**看待这次变更的。变更落地后的文案是「这周这样更合适」「上一阶」，不是「我帮你减了两组」。同样是减量，前者是调整，后者是道歉。

**Considered options**：① 加量自动、减量确认。理由是信息价值不对称——但这偷偷设了一个例外：「好消息不需要同意」。而剂量回路的第一次加量往往发生在用户最没把握的时候（刚练两周），此时「App 自己把重量加上去了」和「App 说可以加了，我点了」是两种完全不同的心理事件；前者是替他决定，后者是给他证据。② 全部自动、事后可撤销。省交互，但撤销的前提是用户记得原样，而记得原样的人本来就不需要被调整。③ 全部提案、每次训练后都提。最尊重，但把周尺度的事做成了日尺度，提案本身变成骚扰，尊重就变成了负担。

**Consequences**：`Gate` 里不再有 `.applied`，只剩 `.proposed` / `.notEnoughData` / `.refused(safety)`。`revision` 只在**采纳**时 +1，未采纳不计数——否则「第几版」会把没发生的事算进去。ADR-0003 收窄为它的特例。拒绝必须有后果：同一条建议不重复提；连续三次拒绝，停止提案一个周期。否则「尊重」会退化成纠缠。提案频率一周一次，唯一例外是停练重建——那一次必须在用户下次打开时立刻出现，因为等一周后他已经不打算回来了。
