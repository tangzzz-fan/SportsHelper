**核查结论（未改代码）**

- **一句话生成是半成品**：`AIPlanClient.generatePlan(profile:extraNote:)` 早就支持 `extraNote`，三级降级 / 64KB / `PlanValidator` 都在；但 `AIGenerateCard` 调它时写死 `extraNote: ""`，用户没有输入句子的地方。`AIPromptBuilder.userBrief` 也已把 `extraNote` 渲染成「补充要求」。

**ask-matt 路由**：多会话构建 → grill 澄清 → to-spec → to-tickets。项目已有 FROZEN + SPEC 与 `.scratch/<feature>/issues/` 本地看板，跳过重写 spec，直接落票；文档补丁单独一票。

**四个产品决策（用户选定）**

1. 输入：文字 + 语音（Speech 转写回填）
2. 冲突：生成前先「我理解为…」；本次覆盖档案，**伤病只增不减**，不写回档案
3. 播报：关键节点 + 休息最后 3 秒倒数

**看板**：`.scratch/brief-and-voice/`，10 票。前沿 = 01 文档补丁 / 02 `PlanBrief` 解析 / 05 AI 传输层可测化 / 07 播报文案。关键依赖：03 确认页 ← 02；06 语音输入 ← 03；04 接线 ← 02,03,05；09 挂流程 ← 07,08；10 真机验收 ← 06,09。

## 导入解析两处实测缺陷已修（19:06）

- **意图反转**（严重）：「我最近肩颈不适」原来解析成 `focus=["肩部"] + avoid=["颈不适"]`——同时认为「重点练肩」和「避免颈不适」。根因是 `parseFocus` 词表里「肩」直接映射「肩部」，而 `parseAvoid` 只捞到「颈不适」。修法：先算 avoid，再用等长空格 mask 掉这些短语，最后匹配部位偏好；avoid 正则补「肩颈/颈椎/腰椎/腰背/髋/膝/踝/跟腱」和「酸/僵/麻/不舒服」等词

## 图示风格规范 + 自绘三次尝试的结论（22:05）

### 用户三个问题的答案

1. **不是 GIF**。项目里没有任何 GIF/PNG/webp 动作图。实际是**矢量 path 字符串**编进 `GeneratedFigureData.swift`，每个动作 3 个静止姿势。
2. **SVG 里没有动画**（`grep animate` = 0）。播放靠 `Timer.publish(every: 0.8)` 切 index + 0.12s 淡入淡出。SVG 的 SMIL/CSS 动画在这套架构里用不上——生成器把 SVG 拆成 path DSL，动画信息在那一步就丢了。
3. 现在是 **31 个**有图（不是 18 个）。

### 新增 `docs/FIGURE-STYLE.md`（唯一维护点）

四节：图示真实形态 / 素材硬规格（可测量）/ 新增动作四步流程 + 四条必校验 / 自绘的能力边界。

关键一条：**素材是 `fill + evenodd`**，两条 path 重叠会把重叠区挖空；自绘若走素材那条路必须让轮廓互不相交，否则得用 `stroked` 模式。

为此给 `ExerciseFigure` / `FigureRecord` 加了 `stroked` 字段（默认 false），`ExerciseFigureView` 支持两种渲染。**当前没有数据用 stroke**，保留是为了让 `Tools/FigureDraw/` 的产物随时能接。

### 自绘：三代实现，结论是不接入

做了 `Tools/FigureDraw/`（`draw_lib.py` 几何库 + `poses.py` 8 个动作坐标 + `preview.py` PIL 预览，不编译 Swift，秒级迭代）。

| 代 | 做法 | 结果 |
|---|---|---|
| 1 | 单线骨架 | 火柴人 |
| 2 | 分节胶囊 | 香肠串，关节两道弧线 |
| 3 | 连续管（斜接补偿）+ 蛋形头 | 木偶感，侧面站姿与跪姿仍会崩 |

**判据是 App 实际显示尺寸 190pt**（不是 420px 大图）：并排看，自绘像木偶，素材有解剖结构、面部朝向、手指、布料褶皱。差距是质的，不是优化不够。

所以决定：**没有素材就不给图，不用简化线稿顶替**。8 个继续走占位（0.16 透明度淡显 + 详情页写「暂无示意图」）。

### 三次尝试里真正学到的

- `torso()` 那种「左右肩 + 左右髋」的四边形只适合正面，侧面画出来是菱形；侧面要用管
