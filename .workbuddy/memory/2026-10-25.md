## 04:05 构建环境：宏报错必须加 -disable-sandbox（修正旧结论）

票 01 落地时撞了 70 个编译错误，全是：
`external macro implementation type 'ObservationMacros.ObservableMacro' could not be found ... swift-plugin-server produced malformed response`

**排查过的三条死路**（别再走）：
1. 绕过 WorkBuddy 沙盒（`dangerouslyDisableSandbox`）——无效，不是外层沙盒
2. `-skipMacroValidation`——无效
3. `xcodebuild clean` / 换全新 `-derivedDataPath /tmp/...`——无效，不是缓存，也不是并发构建抢 ModuleCache

**也不是 Rosetta**：`arch` = arm64、`proc_translated=0`。

**真因**：Xcode 27.1 给编译器加的沙盒挡住了 `swift-plugin-server`，它输出畸形响应。加编译标志即通：

```bash
xcodebuild -project DongKe.xcodeproj -scheme DongKe \
  -destination 'platform=iOS Simulator,id=D16A8318-973E-45CE-936B-94F5FFE3E0EC' \
  -derivedDataPath /tmp/dk-solo \
  OTHER_SWIFT_FLAGS='$(inherited) -Xfrontend -disable-sandbox' \
  build-for-testing
```

**这推翻了跨项目记忆里「`-disable-sandbox` 已验证可省」那条**——在 DroidBerth 上可省，在 Xcode 27.1 + `@Observable` 的 DongKe 上不可省。判断依据不是项目，是 Xcode 版本与是否用到系统宏。裸 `xcodebuild` 现在必挂。

`project.yml` 里没设 `OTHER_SWIFT_FLAGS`，所以不会覆盖项目配置；传 `$(inherited)` 是对的写法。

## 10:20 取舍：先做纠错留痕，而不是变更史或偏好线

董事长问「变更史 还是 等真机数据」。两个都没选，选了第三件：**校对页留痕**。

判据只有一条：**信号是否正在消失**。变更史与偏好线要的数据将来会有（采纳会再发生、跳过会再积累），晚做只是晚；而校对页的原值 `row.sets` / `result.sets` 只在 `onApply` 那一瞬同框，`PlanEditing.updateItem` 一执行就永久覆盖。每一个没记下的导入都是一次不可恢复的丢失。**只有这一类够格插队。**

落地：`CorrectionMemory`（Core，147 行）+ `CorrectionStore`（UserDefaults）＋两处接线（`ImportView.parse` 应用、`PlanReviewView.onApply` 记录）。单测 653 条 / 2.0 秒全绿。

**三个口径，以后别改错**：
1. 计数是**连续一致**不是累计一致——第二次改成别的值就清零重来。累计会把三周前的旧想法一直套在今天。
2. 只记组数与每组量，**不记休息时间**（噪声），**不记库外 id**（记住假 id 会污染所有同名行）。
3. 生效时改的是**解析结果**（`parse()` 里），不是已存计划；每处改动写进 `assumptions`，卡片前排显示，「你连着 2 次这么改」。同一动作多天只说明一次，超过 4 处折成一句——卡片翻不下就等于没说。

**变更史为什么暂缓**：要存提案正文，而「我的计划为什么变了」与「我有没有在进步」需要两份不同记录，现在没有真实采纳数据判断用户问哪个。写进 BACKLOG §11「还没做的」，触发条件=真机上跑过一次采纳。

**偏好线为什么暂缓**：需要多次跳过同一动作的样本，且没有外部标准答案可依（剂量有 ACSM、依从性有 Henry，偏好没有）。凭想象定阈值就是重犯 04–12 之前那种错。
