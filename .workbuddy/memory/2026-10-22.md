### MCP 报错定案（21:32）

- 证据链：会话启动时注入的 MCP 配置（`ps` 里可见 `--mcp-config`）仍指向 `~/Developments/open-design/apps/daemon/dist/cli.js`；原样复跑得 `Error: Cannot find module ...`，exit 1 → stdio 立刻关闭 → 客户端报 `-32000`。`~/.workbuddy-ai/mcp-tool-list.json` 的 mtime 停在 21:05（会话启动那一刻），里面没有 open-design 条目，说明扫描当场就失败、之后不重试。daemon 本身健康（0.23.1，7456 在听）。
- 处置：① 修 `~/.workbuddy-ai/mcp.json` 的路径与 `OD_DATA_DIR`；② 补软链 `~/Developments/open-design → ~/open-design`、`~/.od → ~/Developments/Open-Design-Projects/.od`，让当前会话那条旧配置也能启动（复跑 exit 0，initialize + 22 tools 通过）。软链可删，重启后以修好的 mcp.json 为准。
- 教训：MCP stdio 服务器的「连接关闭」几乎总是被 spawn 的命令本身退出；先原样复跑那条 command+args，看 stderr，不要去查客户端。

## 素材路线改判 + grilling 三轮定案（22:2x）

**用户裁决：不上架、不考虑授权 ⇒ 用 `bryllim/workout-guide`（Everkinetic 重描，媒体 CC BY-SA 4.0）。** 之前否决它的两条理由（授权 + 两次下载失败）都不再成立。

- 事实（已核）：302 动作、**每动作恰 3 帧**、512×512 透明 SVG、**单条 `<path fill-rule=evenodd>` 实心剪影**（不是线稿）、SVG 中位 18KB、18 动作 ×3 帧 ≈ 1MB。18/18 全覆盖，`shoulder_press` → `seated-dumbbell-press`（`machine-shoulder-press` 是干扰项）。
- 对比过的另两个：`yuhonas/free-exercise-db`（873 动作 2 静图、Unlicense 零义务、**缺 4 个动作**）、`hasaneyldrm/exercises-dataset`（1324 GIF 180×180、媒体 © Gym visual 需署名）。18 动作打包都只有 1.7–1.9MB ⇒ **打包进 App，不做首启下载**。
- 定案：① 素材 bryllim；② 动作库仍锁 18；③ **部署版本 iOS 18 起**（原生玻璃在 26 上才生效 ⇒ 双路径，封装成单个 `GlassSurface`）；④ 动画**默认静止、点按才播、循环到再点**；⑤ 接入走**代码生成**（SVG `<path d>` → SwiftUI `Path` 常量，零第三方转换器）；⑥ 骨架整体删除，只留一张静态占位图做 `_generic`；⑦ 静力动作只取第 1 帧不循环；⑧ 剪影填 `label` + tint 12% 光晕；⑨ 图示按**路径 boundingRect autofit**；⑩ 旧文档一并改到位（FROZEN 决策 6 / SPEC §11§12 / figure-specs 作废 / tokens `figurePolicy`），只由 lead 单点改。
