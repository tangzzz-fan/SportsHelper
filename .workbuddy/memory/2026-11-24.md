## 本轮落地

- **模型合并**：只保留 `DongKeCore/Workout/WorkoutCheckpoint.swift`，加 `revision` / `status`；手写 `init(from:)` 给老断点兜默认值（老存档没有这两个字段）。
- **AppGroupsStore 重写**：容器 URL 可注入（测试用临时目录）；JSONL 用 `O_APPEND` + `flock`；读用共享锁；坏行跳过；条件删除在锁内读—过滤—重写；清空用截断不删文件（避免别的进程写进已 unlink 的 inode）。
- **PendingSetLog 信封**：`{log, sourceDevice, timestamp}`，`sourceDevice` 不写进 `SetLog`/SwiftData。
- **合并口径**：存储层按 `(sessionId, setIndex, sourceDevice)` 去重；`SessionLedger.merge` 再按账本自己的键折叠跨设备同组，完成率不翻倍，iPhone 优先。
- **iPhone 接线**：`WorkoutSession.saveCheckpoint` 双写 UserDefaults + App Group（`revision = plan.revision`）；训练结束 / 清空全部数据时一起清。
- **Entitlements**：`DongKe/DongKe.entitlements` + `project.yml` 加 `group.com.dongke.shared`。模拟器 `simctl get_app_container … groups` 已能列出该组；真机需先在开发者后台注册。
- 文档：`docs/specs/IWATCH-APPGROUPS.md`；`IWATCH.md` §2 与 tickets 同步修正。

## 关键事实：App Group 不能跨设备

`IWATCH.md` 原方案「Watch 通过 AppGroups 追加到 iPhone」不成立。App Group 只在同一台设备内共享；iPhone ↔ Watch 必须走 WatchConnectivity。现在的分层：App Group = 每台设备自己的 checkpoint/outbox；WCSession = 传输层（未实现）。
