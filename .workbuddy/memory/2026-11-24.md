## 本轮落地

- **模型合并**：只保留 `DongKeCore/Workout/WorkoutCheckpoint.swift`，加 `revision` / `status`；手写 `init(from:)` 给老断点兜默认值（老存档没有这两个字段）。
- **AppGroupsStore 重写**：容器 URL 可注入（测试用临时目录）；JSONL 用 `O_APPEND` + `flock`；读用共享锁；坏行跳过；条件删除在锁内读—过滤—重写；清空用截断不删文件（避免别的进程写进已 unlink 的 inode）。

- 文档：`docs/specs/IWATCH-APPGROUPS.md`；`IWATCH.md` §2 与 tickets 同步修正。

## 关键事实：App Group 不能跨设备

`IWATCH.md` 原方案「Watch 通过 AppGroups 追加到 iPhone」不成立。App Group 只在同一台设备内共享；iPhone ↔ Watch 必须走 WatchConnectivity。现在的分层：App Group = 每台设备自己的 checkpoint/outbox；WCSession = 传输层（未实现）。

## W2.4 写入门禁 + 一个迁移级发现（同日续）

- `WatchLogInbox`（DongKe/Services）：读 App Group outbox → 活跃会话交给 `WorkoutSession.ingestRemoteLog`
  （按 `SetLogKey` 去重）→ 无活跃会话直接 `SetLogStore.addIfAbsent` → **落库成功才删 outbox 条目**。
- `SetLogStore.add` 改为返回 Bool；新增 `addIfAbsent`（按 `SetLogKey`）。`SetLogKey` 提升为 public。
- 模拟器端到端验证：往 `workouts/pending-logs.jsonl` 写一条日志 → 重启 App → `ZSETLOGENTITY` 0 → 1，
  pending 文件清零；再写一条同账本键、不同 id 的日志 → 仍为 1 条，证明去重门禁生效。
- **迁移级发现**：加 App Group 后 SwiftData 的 `ModelConfiguration()` 默认 `groupContainer: .automatic`
  会把整个 `default.store` 搬进共享组，老用户升级后本地库看起来全丢。已改
  `ModelConfiguration(groupContainer: .none)`，并把排查方法写进 HANDOFF §6.33。
- `catch` 的内存库兜底现在 DEBUG 打 `ModelContainer failed:`。
- 遗留：无活跃会话时直接落 `SetLogStore` 不更新 `SessionEntity`，历史页的「训练天/会话列表」可能少一次；
  主要链路（iPhone 起训、Watch 打组）不受影响。
